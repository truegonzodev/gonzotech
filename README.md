# 🦝 Gonzo Tech

> Хардкорный научно-индустриальный мод про энергетику и астроинженерию для **Minecraft 1.21.4 (NeoForge)**.
> Единая вселенная прогрессии: **пар → тепловая энергетика → деление → кремний/литография → термояд → токамаки → ИИ → космическая инфраструктура → сферы Дайсона → антиматерия → чёрные дыры → квантовый вакуум → червоточины → божественный контроль над пространством.**

## 🌍 Философия и Ключевой Принцип

1. **Физика мира детерминирована и едина на всех сидах:**
   - Температуры плавления, теплопроводность, КПД турбин и реакторов, радиация и свойства материалов — константы. Игрок один раз учит физический язык мода и может применять знания в любом мире (Thaumcraft-style).
2. **Сид мира меняет ТОЛЬКО замок исследования:**
   - Сид генерирует уникальный скелет уравнения на Зелёной Меловой Доске (какие переменные зафиксированы, какие скрыты вопросиками `?`).
   - Фундаментальные связи между величинами («любовь» и размерности) строго фиксированы.
3. **Качество формулы НЕ влияет на КПД машин:**
   - Единственная цель — достичь **`Баланс системы ≥ 90%`**. Элегантная формула из 3 узлов и «Франкенштейн» из 30 узлов одинаково разблокируют технологию.

## 🧱 Последний инженерный итог: паровая турбина и Smart CTM

- Паровая турбина собирается только как полный прямоугольный параллелепипед: оболочка из casing-блоков с допустимыми node-заменами и роторы во всём внутреннем объёме. Любая часть открывает общее GUI.
- Сервер сохраняет у casing только `formed`; информация о рамке, портах и углах не попадает в BlockState и не требует тысяч model variants.
- На клиенте одна Smart CTM baked-модель при пересборке render section рассчитывает восемь соседей каждой из шести граней. Затем она берёт неизменяемые quads из cache по ключу `(face, mask)` — соседей во время каждого кадра не сканирует.
- Каждая грань разбита без наложений на зоны `2 / 12 / 2`: base texture, 16×2 line, 2×2 outer corner и 2×2 inner corner. Правило `N + E + !NE` создаёт inner corner на диагональном casing вокруг node-отверстия.
- Для Smart CTM отключён ambient occlusion: составные texture quads больше не получают ложные прямоугольные AO-тени от соседнего полного блока. Коллизия и culling скрытых граней остаются обычными.

## 🔥 Продвинутый парогенератор (многоблок 5×5×5)

- **Форма фиксирована**: ровно 5×5×5. Внешний слой — блоки `second_steamgen_casing` (с допустимыми node-заменами на порты), внутренность 3×3×3 — ядра `second_steamgen_core` и/или драгоценные блоки-теплообменники. Контроллер — ядро в углу `(minX+1, minY+1, minZ+1)`. Любая часть открывает общее GUI.
- **Порты (минимум по одному каждого вида)**: GTH-вход (тепловая/универсальная нода), вода (водная/универсальная жидкостная/универсальная нода), пар (паровая/универсальная жидкостная/универсальная нода).
- **Конверсия**: за одно «событие варки» тратится `15 mB воды + 11 GTH` и вырабатывается `12 mB пара × M`. Машина каждый тик делает максимум событий, что позволяют потолок выработки, запасы воды/GTH и место в баке пара. Остатки событий и пара косятся в milli, поэтому малые мощности не «застревают».
- **Множитель теплообменников** `M = 1 + E_avg·(1 + 0.1·(n−1))`, где `E_avg = (C+H)_{avg}/200` по всем `n` теплообменникам. Ядра задают throughput (`34 mB/т` базово на ядро, ДО множителя), теплообменники — только эффективность: на единицу пара уходит `15/(12M)` mB воды и `11/(12M)` GTH.
- **Базы на ядро** (линейно от числа ядер): вода `488 mB`, пар `1526 mB`, GTH `4096`, пропускная способность жидкостей `128 mB/т`.
- **Паразитика**: пассивное остывание `2 GTH/t` и утечка `1 mB` пара/т — независимо от нагрузки (только пока сформирован и ресурс есть).
- **Теплообменники** — любые металлические блоки мода, значения C/H берутся у материала-хоста из `AlloyMaterialCatalog` (например, платина: C 75 + H 75 = 150 → E 0.75). Ванильные блоки подключаются явным списком в `SteamGenHeatExchangers.VANILLA_EXCHANGERS`.
- **GUI**: три шкалы — GTH, вода, пар (раскладка 1:1 с котлом). Тултипы показывают ёмкости, фактические потоки приёма/отдачи, число ядер и бонус теплообменников.
- **Сборка**: Smart CTM, как у турбины. Сервер сохраняет у блоков только `formed` (+`controller` у ядра); порты, ядра и теплообменники — в NBT контроллера.
- **Прогрессия**: пароген — машина Открытия 2. Крафт корпуса/ядра до Открытия 2 даёт `botched_mechanism`; в книге рецептов и в витрине второго открытия (креатив-вкладка) — только после. Рецепты: корпус — стальная пластина/железо/железо, прутья/чугун/прутья, железо/железо/стальная пластина; ядро — чугун/железный люк/прутья, пластина/котёл/пластина, конденсатор/железный люк/чугун.

- *Книга рецептов* (`RecipeUnlocks`): tier 1 — машины/логистика Открытия 1 + стройматериалы II; tier 2 — пылевые сплавы верстака; tier 6 — сверхплотный лёд; отдельно: 3 рецепта после 20 минут наигранных в мире и «всегда» (доска, псевдокатушка, заметки, botched_mechanism).

## 🧪 Система сплавов (custom_alloy)

- **Завод сплавов** принимает 25 произвольных слитков (`AlloyFoundryRecipes`), прогресс плавления — отдельная шкала; результат — один предмет `gonzotech:custom_alloy` с составом в data component (доли металлов), а не отдельными предметами на пропорцию.
- **Свойства** считаются по весам из `AlloyMaterialCatalog`/`AlloyProperties`: прочность, температура плавления, твёрдость, проводимость, радиозащита, **инертность** и пр. Именные пресеты (чугун, сталь, нержавейка, кортен…) — каталогизированные составы.
- **Тинт**: взвешенный цвет состава окрашивает предмет (клиентский тинт-источник `AlloyTintSource`/`AlloyClient`), включая одежду.
- **Снаряжение**: кирка и меч из сплава; полный набор брони (нагрудник/шлем/поножи/ботинки) — крафт из одного точного состава, статы ×множитель слота (×1.0 / ×0.5 / ×0.7 / ×0.4 на ВСЕ статы включая прочность). Одетая броня рендерится через equipment-ассет `assets/gonzotech/equipment/custom_alloy.json` (1.21.4-канон `entity/equipment/humanoid{,_leggings}`), оба листа дизейбл-окрашиваемы.
- **Зачарование**: меч/кирка/броня в ванильных item-тегах `#minecraft:enchantable/*`; сплавы с инертностью ≥ 50 незачаровываемы (компонент ENCHANTABLE не ставится).

## ⚗️ Вода и реактивный цесий

Контакт с водой опасен для поллуцита (`raw_cesium`), цезиевых ore BlockItem-ов, слитка, самородка, пыли и BlockItem цезиевого блока-хранилища. В инвентаре игрока в воде сохраняется установленный ритм: взрыв силой 1 каждые 8 тиков. Выброшенный в воду реактивный stack взрывается один раз, расходуется и не создаёт бесконечную цепочку тиков.

ЦФ1УР не является безопасным обходом: её операция использует настоящий кипяток, поэтому выпуск `cesium_dust` вызывает тот же разрушающий взрыв силы 2, что и печи. Добавлены furnace и blast-furnace recipes `cesium_dust → cesium_ingot`; обе печные ветки уже проверяют произведённый `cesium_ingot`, поэтому также взрываются. Дробилка намеренно не использует этот side effect.

## Ядерная топка, кориум и вольфрамовый абсорбер

- **Ядерная топка** (Discovery 2): один слот топлива, 8 видов уран/ториевого топлива (слитки, самородки, блоки, необработанные уранинит/торианит), горит с постоянной генерацией 262 GTH/t, отдача до 488 GTH/t, буфер 68 408 GTH, пассивная потеря 0,2 GTH/t. Горячий буфер сокращает время горения топлива до −25% (линейно от 22 040 GTH). Крафт: паровая топка по центру, **свинцовый блок** слева, **вольфрамовый слиток** справа, рамка из 4 свинцовых слитков и 4 стальных пластин; в креатив-вкладке машина лежит в самом конце списка.
- **Горение**: вертикальная шкала burnout между слотами; тултип «Горение: осталось X%» (процент остатка, не секунды).
- **Три полосы компаратора:** `0` → `1` при >50 000 GTH (огненный риск: искры вокруг и поджог стоящего игрока) → `15` при >64 000 GTH (критический).
- **Вероятностные пожароопасные эффекты** (объём 3×3×3 вокруг машины, один бросок раз в секунду):
  - **>50 000 GTH** — 5% шанс, что на одном случайном горючем блоке разгорится огонь;
  - **топка, >64 000 GTH** — 3% шанс, что один случайный незащищённый блок плавится в **расплавленный кориум**. Первые 20 секунд после преодоления 64 000 GTH сама топка защищена; если GTH держится выше порога без сброса (любое падение ниже 64 000 заново запускает таймер), топка **сама становится кандидатом** и может расплавиться в источник кориума;
  - **вольфрамовый абсорбер, >94 000 GTH** — 3% шанс, что один случайный незащищённый блок плавится в **лаву**.
- **Расплавленный кориум** — лаво-подобная жидкость (`molten_corium` / `flowing_molten_corium`), зачерпывается ведром кориума и разливается источником. Поведение как у лавы: **жжёт и поджигает сущности** (урон от лавы, 15 с горения), **поджигает горючие блоки**, кислорода не требует. Реакция с водой повторяет схему ванильной лавы: **источник + вода → блок кориума** (застывший, аналог обсидиана), **поток + вода → `dead_stone`**, **распространение вниз в воду → `dead_stone`**. Текстуры — собственные анимированные (`still` 16×128, 8 кадров; `flow` 32×128, 2×8 кадров).
- **Защищённые от плавления блоки:** обсидиан, плачущий/карминный обсидиан, bedrock, barrier, командные/структурные блоки, **долговечный бетон**, сверхплотный лёд, вольфрам, VR-20, стеллит; а также воздух/пещерный воздух/пустотный воздух/структурная пустота.
- **Вольфрамовый блок** — пассивный абсорбер со скрытым буфером 112 000 GTH: принимает тепло (до 488 GTH/t) только через примыкающие HEAT-трубы/узлы, рассеивает 66 GTH/t + **32 GTH/t за каждый примыкающий блок сверхплотного льда**; >50 000 GTH — искры, >94 000 GTH — плавление блоков в лаву. HUD гаечного ключа показывает уровень нагрева.
- **Сверхплотный лёд:** 8 синего льда + 1 стеллитовый блок. Крафтится всегда; в книге рецептов появляется с **Открытием 6** (Токамак).

## 🖥️ GUI-система «слоёный пирог»

Все машины используют общую клиентскую базу `MachineScreen` под рисованный PNG:

- **Лист** — единый PNG 512×512: Classic — `textures/gui/classic/`, NEO — `textures/gui/neo/`; окно 176×166 живёт в центре листа (блит от `(128,128)`), рисунок может торчать за окно до 128 px во все стороны. Окно в арте — 176×167 с левого верхнего угла `(128,127)`.
- **Пути тем:** каждый экран явно задаёт свою пару `machineGui(classicFile, neoFile)`. Classic можно делить между машинами с одинаковой раскладкой; NEO-файл всегда отдельный для каждого станка/уровня. Например, first/second accumulator используют общий `classic/accumulator_gui*.png`, но отдельные `neo/first_accumulator_gui*_neo.png` и `neo/second_accumulator_gui*_neo.png`. Подробное правило — [GUI texture convention](docs/GUI-TEXTURE-CONVENTION.md).
- **Слои (сверху вниз):** Z3 предметы+тултипы (ванила) → Z1 передний PNG с дырками → Z0 проявляющиеся шкалы → Z−1 задний PNG.
- **Без чтения PNG на CPU (0.3.28):** фон → шкалы → передний GUI. Шкалы ограничиваются своей Java-геометрией и процентом заполнения; `GuiMask` и его cache удалены.
- **Шкалы** — «проявление» текстуры без растяжения: `drawVBarTex` (вертикальная, тайл 16×16, привязка к низу — рост без сдвига паттерна), `drawHBarTex` (горизонтальная, слева направо), `drawHBarTexFull` (единая не тайлящаяся текстура, напр. 68×16 прогресс генераторов булыжника).
- **Слоты** — 16×16 физических, гэп 2px; раскладка в меню, позиция = левый верхний угол физического слота; `quickMoveStack` индексный, поэтому переносы раскладки безопасны.
- **Тултипы**: ценники ресурсов (GTH/GTU/вода/пар/кипяток) — у всех мехов; **процентные тултипы прогресса («Дробление: N%», «Генерация: N%», «Переплавка: N%», «Измельчение: N%», «Сплавление: N%», «Усталость») — только у тир-2 мехов**; у паровых тир-1 на прогресс-шкалах тултипов нет.
