# Рецепты и доступность контента

База: 0.3.332 / bc1da5bc. Источник: A4. Приоритет P2. [Карта пакетов](<00 — Карта пакетов.md>).

## CONTENT-1 — Minecraft отвергает рецепт дробилки III

Файл: [third_grinder.json](../src/main/resources/data/gonzotech/recipe/third_grinder.json).

В key есть G = gonzotech:second_grinder, но pattern равен PHP / P P / PSP и не использует G. Нативный загрузчик сообщает: `Key defines symbols that aren't used in pattern: {G}`. Этот рецепт отсутствует в загруженном наборе. Обычный JSON-валидатор проходит, поскольку синтаксически файл корректен.

Задача: восстановить задуманный крафт, согласовав key и pattern. Сверить PROGRESSION/MACHINES/JEI и историю. Если источник не определяет использование second_grinder однозначно, запросить выбор автора. Не удалять G лишь ради зелёного лога, если это убирает требуемую предыдущую ступень машины; не придумывать ингредиенты.

Приёмка:
1. Нативный запуск/перезагрузка ресурсов без ошибки этого рецепта.
2. RecipeManager содержит gonzotech:third_grinder и корректный выход.
3. Задуманный рисунок крафтится, неверный — нет; расход ингредиентов соответствует выбранному рецепту.
4. JEI/доступ по прогрессии проверены отдельно: наличие JSON не равно доступности в игре.
5. Регрессия должна падать на исходном unused-G варианте. Добавить контроль ошибок загрузки рецептов, чтобы общий GameTest PASS не скрывал отказ ресурса.

Границы: не делать массовый балансный проход по рецептам и не активировать старые концепты из info. Обновить затронутые PROGRESSION/MACHINES/JEI, CURRENT/HISTORY/AUDIT. Согласовать проверку загрузки с пакетом тестов, не дублировать два независимых фикса одного рецепта.
