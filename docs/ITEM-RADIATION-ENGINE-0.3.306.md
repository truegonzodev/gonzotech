# Внешняя радиация предметов — 0.3.306

Реализация для Minecraft 1.21.4 / NeoForge 21.4.157. Работа велась только в `D:\FAZO\gonzo tech mod chatGPTs`.

## Что изменено

- Наведённая радиоактивность и время последнего расчёта больше не читаются и не записываются в компоненты / NBT ItemStack. Природная эмиссия, экранирование, формулы роста/спада и шкала игрока сохранены.
- `ExternalRadiation` хранит серверные значения в слабом индексе экземпляров ItemStack. Это внешний runtime-индекс с обязательными адаптерами копирования/переноса, а не отложенная запись компонентов. Сам индекс не обходится как список источников: источниками остаются только реальные инвентари и сущности.
- Постоянное сохранение — отдельная таблица `GonzoItemRadiationV2` у владельца: игрока, block entity или entity. Адрес — слот владельца, вложенные слоты записываются рекурсивно до глубины 4. В таблице есть проверки типа и количества. В сериализацию ItemStack эта таблица не добавляется.
- Удалены `RadDoseIndex`, `RadiationClickWatch`, виртуальное held-состояние, радиационный clamp количества и клиентский `RadReequipGate` с его миксином. Нет ожидания окончания кликов и последующего flush в предметы.
- Значение радиоактивности выводится отдельной панелью над обычным tooltip; при нехватке места — ниже. Сам tooltip и предмет от этого не меняются. Токсичность остаётся обычной строкой tooltip.
- Оба одноштучных слота карт Плотника теперь учитывают свой лимит и при Shift-переносе. Излишек остаётся у игрока.

## Модель количества и переноса

Внешнее значение — скорость излучения **одной единицы**. Для стопки отображается и учитывается `rate * count`. Это не запас конечных квантов: радиационные формулы продолжают изменять скорость во времени.

- Разделение 64 предметов с rate=1 даёт суммарно те же 64 единицы эмиссии.
- Объединение `1 × rate=1` и `1 × rate=2` даёт `2 × rate=1.5` (сумма 3).
- Разная наведёнка больше не мешает ванильному стакингу: она отсутствует в сравнении компонентов. Все остальные ограничения стакинга остаются ванильными.
- Обёртка серверного клика учитывает фактический результат операции. Для QUICK_CRAFT отдельно сохраняется вклад предметов, уже лежавших в целевом слоте.
- Перехвачены copy/split, подбор в Inventory, воронки, SimpleContainer, Slot.safeInsert, ItemStackHandler, InvWrapper, объединение ItemEntity, мешочки. Добавлены явные вызовы при объединениях в станках и маршрутизации GonzoTech.
- Щипцы и ковш хранят наведёнку содержимого во внешнем состоянии носителя. Выгрузка, копирование, сохранение и экранированная эмиссия учитывают это состояние.
- Новые продукты рецептов по умолчанию создаются без наведёнки. При добавлении такого продукта в уже заражённый выходной стак его вклад считается нулевым; прежняя суммарная наведёнка не размножается. Специальный перенос через преобразование ингредиентов потребует отдельного правила рецепта.

## Креатив и сеть

Креатив присылает серверу готовые слоты, поэтому одного copy-hook недостаточно. `CreativeRadiationBridge` сопоставляет серверное состояние до/после жеста и распределяет только радиацию уже известных удалённых единиц. Новое количество из каталога не получает наведёнку из воздуха. Временное состояние курсора ограничено 64 единицами и проверяется по отпечатку предмета; пустой курсор не оставляет резерв для будущего предмета из каталога.

Клиент отправляет границы жеста, номер меню, последовательность, количество/отпечаток курсора. **Клиент не присылает дозы. Эти пакеты не создают, не удаляют и не заменяют ItemStack.** Отдельные серверные snapshots содержат только значения для отображения, номера слотов и отпечатки. Панель проверяет меню, подтверждение обработки жеста, stateId обычного меню и отпечаток. До подтверждения рисуется многоточие вместо заведомо устаревшего числа. Закрытие меню также завершает барьер.

Креативный протокол ванили не сообщает намерение при перестановке двух полностью одинаковых по компонентам и количеству стопок с разной внешней дозой. При такой неоднозначности сопоставление отдаёт приоритет прежнему слоту, затем переносам. Суммарная наведёнка сохраняется, но индивидуальная история этих двух одинаковых стопок не гарантируется. В обычных серверных меню доступны реальные операции и ссылки на предметы.

## Проверки

`gradle runRadiationTest --no-configuration-cache` запускает отдельный мир `run-radiation-tests`, не пользовательские сохранения.

Набор включает 10 GameTests:

1. copy/split и 1000 обновлений радиации без изменения сериализованного предмета;
2. ПКМ-раскладка в заполненные слоты с разной дозой и последующее объединение;
3. подбор, воронки, ItemStackHandler (включая simulate), дроп и мешочек;
4. сохранение/загрузка сундука и ItemEntity, отсутствие sidecar в item-bound NBT;
5. InvWrapper, SimpleContainer и перенос содержимого щипцов/ковша;
6. серверные креативные пакеты, разделение, учёт дропа и чистые предметы каталога;
7. Shift+ЛКМ по 16 картам при заполненной активной девятке Плотника: 1+1 карты в слотах, 14 у игрока;
8. 2000 случайных PICKUP/QUICK_MOVE/SWAP с сохранением количества и эмиссии плюс 1000 кликов с радиационными обновлениями;
9. сохранение вложенных слотов шалкера, установка и обратная упаковка;
10. сравнение всех 288 вариантов геометрии составных труб с прежним расчётом.

Полный интерактивный сценарий с реальным клиентом, частым ЛКМ/ПКМ/Q и `/tick rate 200` требует ручного прогона. Серверные GameTests проверяют операции и инварианты, но не заменяют проверку клиентского предсказания и внешнего вида панели.

## Границы этой версии

- Старые item-NBT значения не мигрируют. Для проверки нужны новые предметы; старые различающиеся компоненты сами по себе по-прежнему мешают стакингу. Пользовательские миры и предметы автоматически не очищались.
- Произвольные сторонние хранилища, пересоздающие предметы через собственные кодеки, и владельцы только с нестандартными IItemHandler без Container потребуют адаптеров сохранения. Универсальной гарантии для любого мода нет.
- Унаследованная механика щипцов/ковша хранит вид и количество содержимого, а не полный произвольный набор его компонентов; эта версия исправляет внешний перенос радиации, но не переделывает общий формат их содержимого.
- Курсор не добавлен как новый источник облучения: сохранено прежнее правило ядра. Обновление панели само по себе не меняет механику.
- В исходных ресурсах остаётся отдельная ошибка рецепта `third_grinder.json`: ключ `G` объявлен, но не использован в pattern. Minecraft пропускает этот рецепт. Это не ошибка нового движка; рецепт и его баланс здесь не менялись.

## Сопутствующий запуск и сборка

Загрузка тестового сервера показала многократный расчёт одинаковых хитбоксов составных труб. Добавлен ограниченный ключами геометрии кэш (максимум 288 форм), режимы потока/вода не входят в ключ. Все формы проверяются отдельным тестом; геометрия не изменена.

Скопированный configuration cache из папки проекта перемещён в `.gradle/configuration-cache-before-306`. Это предотвращает повторное использование старой конфигурации с абсолютными путями к основной папке. Сборка выполняется в выбранной копии.

Точки входа: `radiation/engine/ExternalRadiation.java`, `MenuDoseTransaction.java`, `CreativeRadiationBridge.java`, `RadiationOwners.java`, `RadiationViewNetwork.java`; клиент — `radiation/client/RadiationPanel.java`.

Документация используемого механизма тестов: https://docs.neoforged.net/docs/1.21.1/misc/gametest/ ; конфигурация запуска ModDevGradle: https://github.com/neoforged/ModDevGradle#runs . API проверены по локальным исходникам именно 1.21.4/21.4.157.
