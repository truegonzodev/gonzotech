# Автошахта: Плотник, сейсмика и буры

Срез кода: **0.3.311**, `c15083f`; документальная база: `42730c3`. Сверка/миграция: 27.10.2026.


## Назначение и цикл

Сектор — 3×3 чанка. Плотник — контроллер питания/построек/сканирования/добычи, рабочие блоки связывают комплекс. Геофон и источник колебаний — разные элементы сейсмики. Пустая карта памяти получает отпечаток сектора; метки — клиентский waypoint-рендер, не блоки, с иконками руд.

Доступный ручной путь сохраняется: метки позволяют копать вручную. Автоматический цикл — расставить/соединить установки → импульс → карта → отметки скважин → буры с расходуемыми трубами → добыча в хранилище Плотника → выгрузка/сворачивание. Обрушение TNT и построечные очереди отдельны от рудной добычи.

## Действующие контракты

- Активная девятка + виртуальные 54 слота, ёмкость предметных партий 512; два карточных слота имеют собственный одноштучный лимит. Shift-перенос не должен превращать слот карты в обычный стек.
- `setItem` заменяет, не дополняет. Выдача и списание привязаны к успешному изменению мира; приёмник/регион/нерушимость проверяются до обещания результата.
- При заполненном приёмнике бур ждёт, не добывает бесплатный выход. `packUp` сначала останавливает бурение/очереди и очищает кэш, затем может закончить ветку «нечего собирать».
- В 0.3.311 rollback резерва возвращает реально извлечённый stack с компонентами/дозой; приоритет активные → депо → добытое сохранён. Стандартный copy без адаптера внешней дозы недостаточен.
- Известный незагруженный чанк — UNKNOWN, не AIR. Не прогревать/не расширять область чтения «для удобства» вопреки контракту N11.
- Выбор двух активных Плотников — гипотеза, не разрешённый фикс. `PlotnickBlock.java` остаётся read-only.

Фактические операции: `PlotnickBlockEntity`, `SeismicSourceBlockEntity`, `PlotnickMenu`, `MemoryCardItem`, `PlotnickButtonPayload`, `MarkerClient`/`MarkerRenderer`. Ранний макет со слотами 10+27+10 и первоначальные foreman/well_pipe названия не являются текущими ID/размерами.

## PERF-001/9 — защита целевой клетки,0.3.332

Плотник запрашивает WG непосредственно перед реальной правкой целевой клетки — не под своим корпусом и не сканом всего3×3. Одна политика для строительства work/drill, установки/замены bore pipe с добычей, бокового всоса руды, демонтажа и TNT replacement. Запрет до материала/правки/выдачи; очереди, количество попыток и обычный retry сохранены. После снятия запрета следующая штатная попытка может продолжить работу; flag-change не является новым принудительным wake-up очереди.

Для **любой** правки нужны оба разрешения `block-place` и `block-break`: каждое — явный ALLOW либо, при UNSET, fallback от `build=ALLOW`. Любой явный DENY place/break запрещает всё; `build=DENY` — безусловный машинный veto. `pistons` обязан быть **явно ALLOW**; UNSET запрещает, хотя стандартный default WG равен ALLOW. Полное отсутствие этих флагов внутри региона не разрешает работу. Приоритеты, одинаковые priority, родители и region groups разрешаются движком WG; субъект всегда NON_MEMBER, без владельца/ближайшего игрока.

`__global__` считается регионом всего мира, не «вне регионов». По отдельному решению автора явный глобальный `build=ALLOW` **может дать fallback**, в отличие от legacy-правила самого WG. Исключение учитывает NON_MEMBER-группу и native priority/ignored-parent/implicit-build barriers: не перепрыгивает локальный build-барьер и не отменяет DENY/прочие флаги. Остальные значения разрешает WG.

WG отсутствует — старые события NeoForge и их кэш, без новых world/region scans. Исправный WG вне регионов разрешает; обнаруженный установленный, но неисправный/disabled provider запрещает с серверной диагностикой, никогда не подставляет nearby player. WG-проверка идёт до no-WG event cache; живые флаги/новый manager проверяются при каждой попытке.

Адаптер использует настоящий Bukkit World с `getHandle()==ServerLevel`, plugin classloaders и `BukkitAdapter.adapt`, затем WG manager/ApplicableRegionSet/flag engine. Никаких догадок world/world_nether/имён dimensions и новых hard dependencies. Детали окружения/перезапуска/границ — [INTEGRATIONS](INTEGRATIONS.md#perf-001-wg332).

Проверки:1326assertions,9mutants/exact331compilednegative;100000вызовов безBukkitAPI,0block/chunkreads. В test исполняются production integration и BE gate/mutation bodies + exactWG7.0.13 flag engine; host/geometry/Guava doubles. Автор не имеет hybrid-стенда: native-приёмка и закрытие9 **ещё впереди**. 12/13/14, D-PLOT1, PlotnickBlock/election/прогрев/радиация/баланс не затронуты.
