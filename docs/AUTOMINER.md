# Автошахта: Плотник, сейсмика и буры

Срез кода: **0.3.311**, `c15083f`; документальная база: `42730c3`. Сверка/миграция: 27.10.2026.


## Назначение и цикл

Сектор — 3×3 чанка. Плотник — контроллер питания/построек/сканирования/добычи, рабочие блоки связывают комплекс. Геофон и источник колебаний — разные элементы сейсмики. Пустая карта памяти получает отпечаток сектора; метки — клиентский waypoint-рендер, не блоки, с иконками руд.

Доступный ручной путь сохраняется: метки позволяют копать вручную. Автоматический цикл — расставить/соединить установки → импульс → карта → отметки скважин → буры с расходуемыми трубами → добыча в хранилище Плотника → выгрузка/сворачивание. Обрушение TNT и построечные очереди отдельны от рудной добычи.

## Действующие контракты

- Активная девятка + виртуальные 54 слота, ёмкость предметных партий 512; два карточных слота имеют собственный одноштучный лимит. Shift-перенос не должен превращать слот карты в обычный стек.
- `setItem` заменяет, не дополняет. Выдача и списание привязаны к успешному изменению мира; приёмник/регион/нерушимость проверяются до обещания результата.
- При заполненном приёмнике бур ждёт, не добывает бесплатный выход. `packUp` сначала останавливает бурение/очереди и очищает кэш, затем может закончить ветку «нечего собирать».
- В 0.3.311 rollback резерва возвращает реально извлечённый stack с компонентами/дозой; приоритет активные → депо → добытое сохранён. Стандартный copy без адаптера внешней дозы недостаточен.
- Известный незагруженный чанк — UNKNOWN, не AIR. Не прогревать/не расширять область чтения «для удобства» вопреки контракту N11.
- Выбор двух активных Плотников — гипотеза, не разрешённый фикс. `PlotnickBlock.java` остаётся read-only.

Фактические операции: `PlotnickBlockEntity`, `SeismicSourceBlockEntity`, `PlotnickMenu`, `MemoryCardItem`, `PlotnickButtonPayload`, `MarkerClient`/`MarkerRenderer`. Ранний макет со слотами 10+27+10 и первоначальные foreman/well_pipe названия не являются текущими ID/размерами.

Лимит1 A/B и динамита проверяется на входе, не после записи стопки. SlotCapacity общий для труб/ванильного переноса/обычного и sided NeoForge handler; при подаче64в свободный нужный слот принимается1, остаток63остаётся вызывающему, занятый слот не принимает ещё. При правильной подаче новые TNT surplus не возникают; старую NBT-recovery не меняли.
