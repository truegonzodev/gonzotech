# Правила разработки GonzoTech

Действующие ограничения; не история патчей. Порядок работы с документами — [DOCS_RULES](DOCS_RULES.md).

1. Не реализовывать идеи, новые механики, рецепты и баланс без конкретного решения автора. Наличие предмета/текстуры/концепта не означает обязательство реализации.
2. Авторские PNG, модели, звуки и координаты не перерисовывать ради тестов или собственного вкуса. Заглушки обозначать как заглушки; замена — только в согласованной области.
3. Баланс-константы, цены, гейты, длительности, расход/генерацию не менять попутно с оптимизацией. При конфликте документа и кода показать расхождение автору, не придумывать баланс.
4. Minecraft 1.21.4 / NeoForge; сверять реальный Mojmap API. MCP-зеркало не является доказательством типа/сигнатуры. Не выдумывать методы. Bracket/parser checks не заменяют компиляцию.
5. Исправление — в источнике дефекта, с регрессионной проверкой, документацией и доставкой. Кодовый фикс получает patch-версию. Документальный проход без runtime-изменений может оставаться под текущей версией с отдельным событием в HISTORY.
6. Коммит/пуш в рабочую ветку разрешены автором. Не включать посторонний WIP; не удалять пользовательские изменения. Версию и результат проверок указывать честно.
7. «Игровой баг подтверждён/закрыт» — только по игровому прогону автора либо явно согласованному игровому доказательству. Source-pin, harness, javac, GameTest и ручная игра — разные уровни доказательств.
8. Автоматическое срезание количества не является лечением дюпа. Проверять источник переноса/создания и серверную сумму, с учётом земли/курсора и легитимного производства; устойчивость после перезахода важна для игрового вердикта.
9. Радиационный runtime не менять без отдельной заявки автора. Авторский движок 0.3.311 уже интегрирован; старое «ждём патч автора» — история. Миграция/очистка legacy-предметов не разрешена и не становится обязательной регресс-задачей.
10. `PlotnickBlock.java` — read-only в действующей области работ. Гипотеза о двух активных Плотниках не разрешает менять выбор лидера. Новая заявка автора может явно пересмотреть ограничение; не делать это молча.
11. Bob/анимационные исправления — визуальные, не вмешательство в физику радиации/инвентаря. Не возвращать удалённые RadReequipGate/held-cache как «защиту».
12. Шалкерный пласт не расширять без нового слова автора. Не путать поддержанный deep-учёт радиации с разрешением переделать хранилища.
13. Радиационные единицы в интерфейсе **везде `/s`**, не `/t`. Внутри rates — nZt/s; менять суффикс не значит пересчитывать баланс. Цвета/формат — через `GtUnits`; обычные скорости других ресурсов сохраняют собственный контракт.
14. GUI: холст 512×512; точные координаты и исключения — [SUPER_CRUCIAL_FILE](SUPER_CRUCIAL_FILE.md). Не выравнивать «на глаз».
15. Classic можно переиспользовать при одинаковой раскладке. Каждый станок/тир имеет собственную NEO-пару. Машинные листы выбираются через `machineGui(classic, neo)`; служебные текстуры — отдельно. JEI использует Classic независимо от темы.
16. `first_`, `second_`, `third_` — семантика прогрессии, но **не универсальная замена явной таблицы гейтов**. Доступ к книге рецептов, физический крафт и открытие страницы различаются; источник — [PROGRESSION](PROGRESSION.md).
17. В функциональной creative-вкладке группу III не смешивать с II. После `third_dispensing_tap` идут `third_grinder`, `plotnick`, `work_block`, `seismic_source`, `geophone`, `miner_drill`, `bore_pipe`, затем литографический блок. Исключения ID не переименовывать ради группировки. Двери/материалы могут принадлежать другим тематическим вкладкам; не сводить всю сортировку к префиксу.
18. Избранное заметок — по миру/игроку; фильтр — временный, отдельно по категории. Не менять стабильные ID страниц; гейт некроза — реально активированное открытие III **И** факт эффекта.
19. Оптимизация не должна менять механику: неизвестный/незагруженный чанк не равен пустому миру; кэш не является разрешением писать в заменённый BE. N5: setItem — замена, не добавление. N11: исходный контракт прогрева 5×5 не расширять самовольно.
20. Региональные ограничения WorldGuard зависят от внешнего server-side bridge; не обещать защиту в окружении без источника флагов. Подробности — [CAPABILITIES](CAPABILITIES.md).
21. Лор сохраняет неоднозначность. Не превращать возможные трактовки в канон/прямую экспозицию. Авторские заметки и предложения ассистента различать.
22. README — публичное превью, **не внутренняя рабочая память**. Не дописывать туда отчёты патчей, ограничения разработки и технические сводки.
23. Перед новым шагом читать RULES → DOCS_RULES → CURRENT-STATE → профильный документ. Архив читать только для происхождения факта/решения; старый статус не переносить автоматически в текущий план.

## Происхождение

Правила консолидированы из авторских уточнений текущей сессии, старых рабочих заметок и фактических ограничений предыдущих раундов. Полные исходные записи сохранены в [карте миграции](archive/legacy-0.3.311/MIGRATION-MAP.md). Этот список не даёт новых разрешений на runtime-работу.
