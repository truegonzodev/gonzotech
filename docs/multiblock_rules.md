# Правила мультиблоков

**Версия:** 0.3.77 · **Статус:** обязательны к каждому новому мультиблоку.
Цель — не мараться по 324 фикса на каждую машину: любой PR по мультиблоку
проходит по этому чек-листу до пуша. Референсы реализации: `TurbineStructure`,
`SteamGenStructure`, `BlastFurnaceStructure`, `FormedMenus`, `StructureModel`.

## 1. Деинициализация = полный сброс

После распада структуры в мире не остаётся призрачных состояний:

* шкалы/буферы/процессы — обнуляются (burnout, прогресс, аккумуляторы);
* содержимое — ВСЁ выпадает наружу (каждый слот → `Containers.dropItemStack`);
* машина-«остаток» (топка/ядро вне структуры) остаётся абсолютно пустой;
* никакой привязки состояния механизма к блоку-контроллеру: контроллер —
  обычная часть, его слом = разбор всей структуры.

Реализация: `FireboxBlockEntity.dropAndResetAfterDeform` (0.3.75); вызов из
`partChanged` при сломе любой части. Состояние «сформирован» хранится в NBT,
чтобы восстановленная после загрузки мира структура НЕ проходила сброс заново,
а разобранная офлайн — разбиралась по тем же правилам при загрузке.

> **Исключение — реактор (0.3.78, автор):** состояние и симуляция реактора
> ПЕРЕЖИВАЮТ деинициализацию — аварию нельзя предотвратить сломав контроллер.
> Реализация — ванильное BE-хранилище (без кастомных сущностей): подача
> прекращается (порты ввода только у сформированной структуры), процессы
> догорают в NBT-состоянии BE чехлов/панели; ТВЭЛы — в чехлах; авто-очистка
> BE при температуре 0 и нуле нейтронов. Подробности:
> `docs/reactors_concept.md` §5в-3.

## 2. Клик-семантика: GUI vs поставить блок

* **ПКМ** по любой части собранного мультиблока (оболочка, узлы, «вырезанные»
  блоки вроде котла) — открывает общее GUI.
* **Shift+ПКМ** открывает GUI **только если у предмета нет своего
  взаимодействия**: меч, кирка, рука → GUI; **блок → ставится блок**, GUI не
  открывается.
* Механика: проверка в хуках блока части через `FormedMenus.open`
  (турбина → пароген → печь в одном месте); ваниль сама обрабатывает sneaking.
  Ивент `RightClickBlock` — ТОЛЬКО для блоков без своих хуков (ванильный
  котёл), и там обязателен гейт `event.getEntity().isShiftKeyDown()`.
* Меню открывать двухарг-перегрузкой `player.openMenu(provider, pos)` —
  одноарг не пишет extra-data → NPE `readBlockPos` на клиенте → дисконнект.
* **Исключение — реактор (эпоха 3+, автор):** доступ к GUI — **ТОЛЬКО через
  панель управления**; ПКМ по обшивке/узлам реактора меню не открывает.
  Правило «любая часть открывает GUI» действует для турбины/парогена/печи.

## 3. Инициализация моментальная

Сборка и разбор происходят **в тот же игровой тик**, что и постановка/ломание
последней части: `partChanged` → `revalidateNow()` (без троттлинга) у всех
контроллеров в зоне структуры. Периодическая ревалидация (20 тиков) остаётся
только страховкой на вход в мир/загрузку чанков.

## 4. Состояния блоков-частей

Валидатор по умолчанию принимает **ЛЮБОЕ** BlockState части (все face-варианты
котлов, топок, ступеней, поворотов). Сужать (например, «котёл только без
воды») — только по явному слову автора. Исключение из правила: если автор
указал конкретное состояние — проверять по `state.is(...)`/свойству, но помнить,
что постановка части с «неправильным» face не должна ломать сборку.

## 5. Разворот по осям

Мультиблоки, несимметричные по двум осям, обязаны собираться при **любом**
`Direction` постановки контроллера. Проверять сборку минимум в 2 ориентациях
(в сьюте — лэйаут-чеками от обеих). Внутренние позиции считать от контроллера
(как `FireboxBlockEntity` от топки), не от абсолютных координат.

## 6. formed-текстура — только обшивка

FORMED-флаг и CTM-соединение получает **только блок обшивки**. Узлы, котлы,
«вырезанные» части не красятся и остаются визуально отдельными (как узлы
турбины/парогена). Новый блок обшивки ОБЯЗАН быть добавлен в белый список
`TurbineSmartCtmBakedModel.isFormedCasing` — иначе formed-оболочка рендерится
**невидимой** (ноль квадов), а «вырезанность» остальных видна насквозь.

## 7. Правила, выработанные практикой (0.3.65–0.3.77)

* **Кап узлов на структуру.** Узлы дешевле обшивки — без лимита всю оболочку
  собирают из узлов. Турбина ≤ 8, пароген ≤ 10 (авторские числа). Для нового
  мультиблока кап спрашивать у автора сразу. Счёт — по позициям обшивки,
  универсальный узел один раз; гейт в `validateBox` (действует и при
  восстановлении после загрузки).
* **chunksLoaded-гейт.** Никогда не читать блоки по кубу структуры без
  загрузки чанков: `hasChunkAt(BlockPos)` по 4 угловым BlockPos — НЕ
  чанковая математика и НЕ `getBlockState` по всему кубу. Иначе вход в мир
  встаёт в очередь генерации («100% hang»).
* **Единицы и тултипы.** Внутри — милли (×1000). Тултипы GUI — в единицах;
  заливка шкалы — одинаковые единицы в числителе и знаменателе (смешение =
  мгновенные 100%). HUD гаечного ключа — простые единицы без «К»-тиров
  (форматтер тирает кило-МИЛЛИ, читается как тысячи). Потери «(+N)» —
  кумулятив маршрута до трубы: растут вдоль потока, max по дорожкам тика,
  сброс каждый тик.
* **Числа автора не пересчитываются.** Неподтверждённое помечать TODO,
  пинить как есть, подтверждение снимать с пина (история: 320 GTH/t →
  144/узел).
* **Скоуп = авторский список правок.** Всё, что не написано, не трогается.
  Валидатор принимает обе трактовки спорного чертежа ТОЛЬКО до первого
  разъяснения автора, потом лишняя ветка удаляется.
* **Пины сьютов.** Покрывают САЙТ ВЫЗОВА, не только внутренности метода
  (урок: потерянный `revalidateBlast` убил печь на 4 версии). Пин-строки —
  по чистому коду, без `//`-хвостов. Один проход патча на файл
  (повторная запись по устаревшему тексту затирает соседние правки).
  Арифметику чеков (счёт блоков и т.п.) пересчитывать до пина числа.
* **Автоматизация задаётся автором по каждой машине** (у доменной печи:
  трубы/воронки только закладывают топливо, извлечение запрещено; вывод GTH
  только через узлы структуры).
* **Кап отдачи на узел.** Выход ресурса из мультиблока — бюджетом на каждый
  узел отдельно (`min(на_узел, остаток)`), никогда «весь буфер в одну трубу».
* **Горячий пересчёт параметров без переинициализации** (реактор, 0.3.78+):
  если содержимое структуры меняется БЕЗ нарушения формы (борный стопор
  задвинут поршнем, вода залита в чехол), это НЕ сборка/разбор — formed-флаги
  не трогаются, структурная валидность не зависит от наполнителя. Параметры
  (реактивность, замедление) пересчитываются по block updates соседей/периодике
  в тот же тик.
* **Компиляция.** Локальная сборка автора — единственный compile-gate для
  MC-классов; с нашей стороны: чистая логика + селфтесты + пины проводки.
  Новому блоку сразу loot-таблица (validate.py), предметная модель
  1.21.4 — `assets/<ns>/items/<item>.json`.
