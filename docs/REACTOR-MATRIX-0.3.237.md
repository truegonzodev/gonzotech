# Отладочные коэффициенты матрицы активной зоны — 0.3.237

**Дата:** 18.10.2026 · **База:** `docs/MatrixCoefficients.zip` · **Статус:** историческая реализация; правило источника и связь с топливом superseded в 0.3.238.

> **Важно:** версия 0.3.237 ошибочно использовала содержимое панели как силу источника и поэтому показывала `H=L=0` при пустом контейнере. В версии 0.3.238 H/L стали сухими структурными коэффициентами: одна фиксированная опорная единица на каждый чехол, независимо от загруженных ТВЭЛов. Актуальные правила и контрольные значения `H=2.6971`, `L=0.8812` для 27 чехлов см. [`REACTOR-MATRIX-0.3.238.md`](REACTOR-MATRIX-0.3.238.md). Физическое хранение ТВЭЛов в чехлах и округление при сломе описаны в [`REACTOR-FUEL-STORAGE-0.3.238.md`](REACTOR-FUEL-STORAGE-0.3.238.md).

## Что делает 0.3.237

При Shift+ПКМ по сформированной панели валидатор повторно проверяет сохранённые границы структуры, затем расчёт читает каждый фактический блок внутреннего куба и строит по нему сетку модели. Гипотетическая/эталонная схема для результата реального реактора не используется. Выходы появляются в сообщении панели: тепловой индекс `H` подсвечен золотым, коэффициент пикового потока утечки `L` — голубым.

- `H` — максимальная локальная тепловая нагрузка после графового теплопереноса, нормированная на калибровочный бюджет. Это игровой безразмерный индекс (может быть выше 1), не температура и не мощность в физических единицах.
- `L` — максимальная утечка через одну наружную грань, нормированная в `[0,1)`. Сообщение показывает и долю, и проценты.
- В сообщение также выводятся количество `uf_tvel` во всех сохранённых местах контейнера панели (включая временно скрытые места), число чехлов и средняя загрузка на один чехол.

## Геометрия, материалы и загрузка топлива

Сторона сетки берётся из сохранённых bounds панели: внешняя оболочка исключается на один блок с каждой стороны. Для каждой внутренней координаты читается текущий `BlockState`:

| Реальный внутренний блок | Материал модели |
|---|---|
| `third_uranium_reactor_fuel_sheath` | `FUEL` |
| блок графита | `GRAPHITE` |
| `boron_block` | `BORON` |
| `barium_block` | `BARIUM` |
| `minecraft:water` | `WATER` |

Подтверждённое правило суперпозиции: если в контейнер панели загружено `T` ТВЭЛов, а в зоне находится `S` чехлов, каждый чехол получает вещественную силу источника `T/S`. ТВЭЛы не округляются и не привязываются к конкретным слотам или координатам; сумма вкладов всех чехлов равна `T`. Базовое `Rules.sourcePerFuel` остаётся равным 1, поскольку конструктор модели запрещает ноль. Если `T=0`, все чехлы получают нулевой источник, и матрица возвращает `H=0`, `L=0` без некорректного `Rules`.

## Свинцовые поршни исключены из сборки

По уточнению пользователя все три типа — `third_lead_piston`, `third_sticky_lead_piston` и `third_lead_piston_head` — удалены из whitelist внутренней зоны. Если любой из них находится внутри реактора, структура не формируется, а диагностика называет недопустимый блок; численные `H/L` не показываются. Блоки и предметы поршней остаются зарегистрированными для иных игровых применений. Материал и коэффициенты свинца не выдумываются и для сборки не требуются.

## Точная модель из архива

Модель — детерминированная безразмерная игровая оценка, не физически валидированная ядерная симуляция. В ней используются 26 направлений, быстрый/тепловой сигнал, рассеяние с фиксированной точностью, графовый теплоперенос и калибровка на эталоне `H=0.70`. Существующие строки материалов:

| Материал | `M` | `Af` | `At` | `C` |
|---|---:|---:|---:|---:|
| `WATER` | 0.90 | 0.05 | 0.15 | 1.00 |
| `GRAPHITE` | 0.55 | 0.01 | 0.02 | 0.10 |
| `BORON` | 0.02 | 0.65 | 0.98 | 0.10 |
| `BARIUM` | 0.05 | 0.10 | 0.20 | 0.15 |
| `FUEL` (чехол, не материал ТВЭЛа) | 0 | 0 | 0 | 0.10 |

Остальные фиксированные настройки: быстрый вес `0.05`, доля рассеяния `0.15`, conduction floor `0.05`, surface cooling `1`, leak half-scale `0.10`, максимум 2000 итераций и tolerance `1e-10`. Эталонный тепловой бюджет `0.162764774544` вычисляется моделью для калибровочной схемы архива; в игровом мире он не пересчитывается по сборке.

## Проверки и границы реализации

- `audit/reactor_matrix_integration_test.py` проверяет, что сетка собрана по сохранённым bounds и live-блокам, ТВЭЛы распределяются равномерно как вещественная величина, стили H/L разделены, а поршни не получают выдуманное соответствие.
- `audit/reactor_matrix_test.py` компилирует исходную модель и Java-оракулы из архива, дополненные тестами суперпозиции и нулевого источника. Для исполнения нужен JDK 21.
- Расчёт вызывается только по Shift+ПКМ; автоматический реакторный тик, выгорание, локальная температура, теплоотвод в воду и выдача GTH здесь не реализованы.
- Свинцовые поршни/головки исключены из внутреннего whitelist; структура с ними не формируется и не доходит до расчёта матрицы.
