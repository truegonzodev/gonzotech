# Пенка жидкостей — обзор перед следующим патчем

**26.09.2026, срез 0.3.21. Только исследование: поведение частиц в этом патче не менялось.**

## Где создаётся

[ModFluidBlock.animateTick](../src/main/java/com/gonzotech/core/fluid/ModFluidBlock.java) — общий клиентский обработчик для шести видов жидкости. Регистрация блоков — [ModBlocks](../src/main/java/com/gonzotech/core/registry/ModBlocks.java), source/flowing fluids — [ModFluids](../src/main/java/com/gonzotech/core/fluid/ModFluids.java).

Это **ванильная цветная пыль `DustParticleOptions`**, не отдельный тип пены и не анимация PNG жидкости. Отдельного серверного потока пакетов для неё нет. Клиентские текстуры/тинт/подводный туман настраиваются отдельно в [CoriumFluidClient](../src/main/java/com/gonzotech/core/fluid/client/CoriumFluidClient.java); их изменение не меняет автоматически параметры этой пыли.

## Точный алгоритм сейчас

1. Вызывает `super.animateTick`.
2. Проверяет **только** `level.getFluidState(pos.above()).isEmpty()`.
3. При `random.nextInt(30) == 0` создаёт порцию **5–10** частиц.
4. X/Z случайны по всему квадрату блока; Y = `pos.y + fluidState.getHeight(level,pos) + random*[0,0.05)`.
5. Масштаб каждой частицы — `[0.5,1.5)`. В `addParticle` передаются скорости **(0,0.015,0)**; дальнейшее движение, вид и время жизни принадлежат ванильному Dust, собственной физики пены нет.
6. Собственного ограничения «только source-блок» нет: применимо и к текущей жидкости, если сверху пустой FluidState.

## Важные места для следующего патча

- Комментарий «каждые 1–4 сек» **не является таймером/гарантией**. Шанс 1/30 относится к вызову клиентского `animateTick`; плотность зависит от выборки анимируемых блоков, размеров поверхности и настроек частиц.
- Сухой полный блок над жидкостью тоже имеет пустой FluidState. Текущая проверка **не исключает крышку/потолок** и не проверяет свободное пространство для частицы.
- Используется одна высота FluidState на всю клетку, а не интерполяция четырёх углов отрисованной наклонной поверхности. На течениях частицы могут не совпадать с видимой поверхностью.
- Пыль появляется порциями, а не равномерно: большой бассейн суммирует независимые порции каждого блока. Общего бюджета поверхности нет.
- Нет отдельной текстуры пузырька, контролируемого времени жизни/распада, привязки движения к поверхности, проверки обрыва потока или отдельной клиентской настройки пены.
- Серверный `entityInside` в том же классе — **другая механика**: раз в 20 тиков накладывает эффекты/токсичность. Визуальный патч не должен случайно менять её.

Перед изменением нужно выбрать желаемые вид, плотность, размер, длительность, движение и поведение под крышкой/на течении. В 0.3.21 ни одно из этих решений не назначено за автора.
