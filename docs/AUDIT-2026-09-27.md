# Актуальный аудит Gonzo Tech — 27.09.2026

**Проверенный срез:** `a49c6ed` / 0.3.25. **Документационная ревизия:** 0.3.26.
**Статус:** аудит кода, ресурсов и документации; не сертификат полной готовности мода.
**Короткий вход:** [AUDIT-CURRENT](AUDIT-CURRENT.md). Исторические аудиты сохранены.

## 1. Главный вывод

У мода уже есть работающий промышленный фундамент, а не только набор заглушек:
Открытия I–II, логистика, материалы/сплавы, начало III с химией и пивоварением,
психика, радиация, чистая комната, авторские интерфейсы и визуальные эффекты.
**Но целостный survival-маршрут Эпохи III ещё не замкнут.** Рабочие механизмы есть,
а способы их получить, узнать рецепты и применить продукты местами отсутствуют.

Следующий правильный шаг — не сразу четвёртая эпоха/новые реакторы, а:

1. стабилизировать клиентский lifecycle и автоматическую проверку сборки;
2. закрыть доступность чистой комнаты и объяснение существующей химии внутри игры;
3. довести ванильные контракты интерфейсов/использования предметов;
4. собрать одну законченную вертикаль «чистая комната → литография → чип → полезный прибор».

**Приоритеты:** P1 — ближайший стабилизационный/прогрессионный проход;
P2 — следующий проход UX/совместимости; P3 — плановый задел.
Ниже отдельно отмечены подтверждённые факты кода, риски для проверки и предложения дизайна.
Отсутствие найденного P0 не означает, что проведён полный security/performance-аудит.

## 3. Незакрытые дыры — по приоритету

### P1-01. Чистая комната работает, но не входит в survival-цикл

**Подтверждено:** нет JSON-рецептов `third_air_cleaner`, `third_air_filter`, `dust_meter`;
другого первичного источника не найдено. Две машины уже включены в физический гейт III,
то есть старый вывод «гейт отсутствует» больше неверен. Гейт сам не создаёт рецепт.
Потребителя качества воздуха в литографии пока нет — линия только спроектирована.

**Дальше:** согласовать состав трёх рецептов и целевой потребитель качества.
Не подменять их произвольными дешёвыми крафтами. Приёмка: новый survival-мир без `/give`,
получение оборудования, комната с 0%, очистка, реальный производственный результат.
Источники: [TierThreeCrafting](../src/main/java/com/gonzotech/machines/crafting/TierThreeCrafting.java),
[CleanRoomSystem](../src/main/java/com/gonzotech/cleanroom/CleanRoomSystem.java), [план литографии](EPOCH3-LITHOGRAPHY-PLAN-2026-09-26.md).

### P1-02. Ложная смерть не очищается при смене игровой сессии

**Подтверждённый дефект lifecycle по коду:** `fakeDeath`, `fakeDeathCause`, `lockTicks`,
`attackWasDown` — static; при `player == null` тик просто возвращается. Сброс `fakeDeath`
есть только в обработчике закрытия ложного экрана. Logout/reset-обработчика у класса нет.
После выхода с активной иллюзией и входа в другой мир состояние может пережить сессию,
включая отпускание мыши. Игровая репродукция в этой среде не выполнялась.

**Дальше:** единый reset на disconnect/смену сессии; проверить также `PsycheNetwork.CLIENT_DATA`.
Не вызывать `grabMouse` из безусловного logout-reset поверх главного меню.
Приёмка: ложная смерть → выход → другой мир/сервер; никаких старых кнопок/захвата камеры.
Источник: [PsycheCrisisClient](../src/main/java/com/gonzotech/core/psyche/client/PsycheCrisisClient.java).

### P1-03. Автоматизированная проверка не равна сборке мода

**Подтверждено:** `.github/workflows` отсутствует; скрипты `audit/` запускаются вручную.
`selfTest` доски — отдельная Gradle-задача, не зависимость `check`.
Полная сборка в этой среде вновь остановилась до компиляции на TLS/EOF загрузки Gradle.
Тесты частей логики и заглушки API не проверяют загрузку Mixin, dedicated server и рендер.

**Дальше:** один воспроизводимый entry point проверок + CI с Java 21, `compileJava`,
`selfTest`, ресурсами и регрессиями. Отдельный smoke клиента/сервера для mixin-ов.
Не менять код геймплея, чтобы «замаскировать» недоступность загрузки Gradle.
Источник: [build.gradle](../build.gradle).

### P1-04. Железная дверь: документация обещала другой коэффициент

**Подтверждено:** старые README/DEFERRED обещали 0.5. Сейчас `RadMaterials.vanillaBlockFactor`
даёт железной двери **0.90**, а `Containment.cell` использует именно этот фактор без
исключения 0.5. Это коэффициент **прохождения**, не процент защиты: 0.90 означает 10% экранирования.

**Дальше:** подтвердить желаемое число и добавить явный тест контракта. В этом аудите баланс
не изменён, README приведён к фактическому 0.90, старое обещание сохранено как расхождение.
Источники: [RadMaterials](../src/main/java/com/gonzotech/radiation/RadMaterials.java),
[Containment](../src/main/java/com/gonzotech/radiation/Containment.java).

### P2-01. Маска GUI не обновляется после resource reload

**Подтверждено:** у `GuiMask` есть static cache и `clearCache()`, но вызовов очистки в проекте нет.
После замены ресурспака/F3+T PNG может стать новым, а отверстия заливок остаться от старого.
Простое переоткрытие меню повторно получает закэшированную маску.

**Дальше:** reload-listener, сброс/пересборка маски в открытом экране; учитывать размер/offset
в ключе, если один PNG начнут использовать разные окна. Приёмка: поменять форму отверстия
в resource pack без перезапуска и проверить заливку на пустом/полном баке.
Источник: [GuiMask](../src/main/java/com/gonzotech/machines/client/GuiMask.java).

### P2-02. Контактная токсичность может начисляться несколько раз за секунду

**Подтверждённый риск:** `ModFluidBlock.entityInside` проверяет только `tickCount % 20`.
Дедупликации на сущность/тип жидкости нет; за один тик callback может вызываться для
нескольких пересечённых клеток. `PsycheChemical.addDoseToxicity` каждое поступление складывает.
В итоге надпись «7 mTx/с» может не соответствовать дозе на границе клеток.

**Дальше:** проверить стояние внутри одной клетки и на пересечении 2–4; затем выбрать контракт
«на игрока/тип/тик» либо дозу от площади контакта. Пока не выдавать это за измеренный в игре множитель.
Источник: [ModFluidBlock](../src/main/java/com/gonzotech/core/fluid/ModFluidBlock.java).

### P2-03. Использование напитков/лекарств не доведено до полного ванильного контракта

**Факт:** у ручных `finishUsingItem` в `DrinkItem`, `CysteamineItem`, `PentacinItem`, `DtpaItem`,
`RadAbsorbentItem` нет явных `Stats.ITEM_USED` / `CriteriaTriggers.CONSUME_ITEM`.
Они реализуют эффект/тару сами; наличие анимации DRINK/EAT ещё не доказывает учёт употребления.

**Дальше:** проверить статистику предмета и тестовое advancement `consume_item`, затем
добавить отсутствующее без двойного срабатывания. Проверить game event употребления, звук,
отмену использования и creative отдельно. Это совместимость, а не изменение дозировок.
Источник: [DrinkItem](../src/main/java/com/gonzotech/core/item/DrinkItem.java).

### P2-04. Для III есть внешняя документация, но мало помощи внутри игры

**Подтверждено:** книга содержит 41 страницу; технологические главы ERA_3–ERA_5 пусты.
Рецепты химзавода/пресса/части переработки — Java-таблицы, не обычные RecipeManager-рецепты.
В репозитории нет JEI/EMI-плагина для них. Наличие рецепта самой машины в книге не показывает
её внутренние процессы, катализаторы, жидкости и возврат тары.

**Дальше:** прежде новых десятков продуктов — страницы/справочник по уже существующей химии,
просмотр причин простоя (не хватает GTU/катализатора/сырья, выход занят) и один источник
данных для выполнения и отображения рецепта. RecipeType/JEI — вариант реализации, не обязательное условие «ваниллайк».
Источники: [ChemicalPlantRecipes](../src/main/java/com/gonzotech/machines/processing/ChemicalPlantRecipes.java),
[ScholarNotesContent](../src/main/java/com/gonzotech/chalkboard/notes/ScholarNotesContent.java).

### P2-05. Сетевое ужесточение доски/кризиса — отдельный следующий проход

Проверка формул и лимиты уже есть — старую проблему доверия произвольному выражению
повторно открывать неправильно. Но в обработчиках sync/save/submit не видно привязки
к серверной сессии открытой доски/дистанции и rate limiting; heartbeat стресса приходит от клиента.
`crisis_click` также вызывает вероятностную перестановку без видимого серверного интервала.
Это **поверхность для hardening**, не доказанный дюп/удалённый взлом в рамках этого аудита.
Приёмка: нормальная частота кликов, спам пакетов, работа вдали от доски, выход во время запроса.
Источники: [ChalkboardNetwork](../src/main/java/com/gonzotech/chalkboard/network/ChalkboardNetwork.java),
[PsycheCrisis](../src/main/java/com/gonzotech/core/psyche/PsycheCrisis.java).

## 4. Предметы: где действительно нет получения/применения

### Метод и цифры

Сформирован воспроизводимый [CSV по всем 504 item-definition](CONTENT-INVENTORY-2026-09-27.csv).
Это число файлов `assets/gonzotech/items`, **не доказанное число runtime-регистраций**.
В `data/gonzotech/recipe` — **611** файлов: явный `result` производит **274 разных mod-ID**,
ещё **6** предметов снаряжения имеют специальные сериализаторы. Итого **224** item-definition
без производящего JSON-рецепта — **не 224 недоделки**.

CSV содержит рецепты результата/ингредиента, item-entry лута и буквальные Java-ссылки.
Он не решает доступность графа, не раскрывает все теги/динамические registry lookup и не
считает self-drop первичным источником. Сам вызов `ModItems.X` не доказывает применение.
Генератор: `python3 audit/content_inventory.py`; проверка снимка: `--check`.

- `polyethylene`, `rubber` — химзавод производит, специализированных потребителей не найдено.

### Ложные тревоги, исключённые проверкой

- Пиво/водка — котёл/кран; ампулы, соль и хлорид кальция — наполнитель;

- `discovery_1…16` выдаются системой открытий, не верстаком; отсутствие буквальной ссылки

**Не является долгом само по себе:** «Телифон», голос Гонзо, ложная смерть как иллюзия,
