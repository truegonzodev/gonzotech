# AUDIT-2026-09-26 — текстуры, внутренние блоки и радиационный контур

**База:** `2c1fb45` (авторский большой коммит текстур) · **Версия:** `0.3.21`.
**Статус:** изменения внесены, headless/статические проверки выполнены; игровая приёмка открыта.

## 2. Сброс воздуха при строительстве внутри

`INTERIOR → INTERIOR` (обычное разрешённое оборудование/трубы) уже не вызывал сброс. Реальная ошибка — переход `INTERIOR ↔ SEAL` при установке/снятии **внутри** белого блока, узла, фильтра и других допустимых герметичных блоков: их принимали за изменение наружной оболочки.

Фикс в `RoomLedger`: для допустимой мебели внутри уже известного объёма сохраняются комната и качество; повторная проверка сохранённого объёма также принимает такой интерьер. **Но внутренние перегородки не игнорируются:** при установке гермоблока проверяется, остались ли его воздушные соседи связаны без этой клетки. Поиск заканчивается, как только найдены все цели (не более шести), и никогда не выходит за известные ≤2048 клеток. Тест обычной мебели в комнате 9³ требует менее 128 чтений, а не обхода всех 729 клеток. Обычный `INTERIOR → INTERIOR` остаётся O(1); новая проверка выполняется при строительстве, не добавляется в каждый тик.

Буквальная однострочная поблажка заморозила бы наружный объём и сломала разделение на комнаты — от неё отказались. Установка/снятие неразделяющей мебели сохраняет качество; **законченная перегородка** создаёт независимые комнаты с 0%, как раньше. Стены/пол/потолок не получают исключения. Дыра, запрещённый блок/жидкость, даже краткое разрушение и восстановление оболочки по-прежнему сбрасывают качество. При неизвестных соседях нельзя доказать сохранение связности; проверка консервативна и не подгружает чанки. Объекты, уже являвшиеся частью оболочки при первоначальном обнаружении, не переопределяются этим исключением.

Вне основного серверного потока соседние чанки не читаются: отложенные изменения консервативно инвалидируют затронутую чистую комнату.

Во время игровой проверки учитывать обычное загрязнение воздуха грязным игроком: оно осталось и не является сбросом от постановки блока.

## 3. Как действительно работают двойные радиационные стены

Это **логическая заливка полости + дискретные лучи наружу**, а не угловой физический raytrace от каждого источника:

- Каждая достигнутая клетка оболочки учитывается один раз; направление первого попадания BFS — её наружная нормаль.
- По этой нормали перемножаются факторы **не более 8 последовательных блоков, включая первый**. Воздушный промежуток/открытая дверь обрывает толщину; нейтральная сплошная облицовка даёт ×1. Незагруженная часть не добавляет защиты и не загружается ради проверки.
- Затем берётся среднее по оболочке. Одиночный наружный блок меняет только пересекающие его лучи, а не включает признак «вся коробка двухслойная».
- Для полости из одной клетки с шестью свинцовыми гранями: без добавки фактор **0.02**; барий за одной гранью — `(5×0.02 + 0.02×0.10)/6 = 0.017`; за всеми шестью — **0.002**. Два полных слоя свинца дают 0.0004, округляемое до нуля порогом **<0.001**.
- Чистые заслонки исключаются из среднего, пока их не больше половины оболочки. Экранирующая дверь учитывается своим материалом.
- Защита ограничивает подпитку загрязнения, **не стирает уже накопленный фон чанка**. Старый фон затухает по прежним правилам.

Подтверждённые соседние ошибки исправлены: открытая металлическая дверь/люк не превращается обратно в стену через коэффициент материала; кэш теперь разделён по `ServerLevel`, инвалидируется реальной мутацией стен/наружных слоёв/источников и сбрасывается при загрузке/выгрузке чанков. Раньше ключом была только позиция, а изменение стены могло ждать TTL 400 тиков.

Алгоритм вынесен в проверяемый `RadiationContour`; материалы, среднее, порог и 8 слоёв сохранены. Соседние радиоактивные блоки больше не выступают ложной оболочкой друг для друга. Один снимок полости повторно используется для её внутренних клеток/источников: 17-й и последующие блоки в **той же закэшированной комнате** не теряют защиту. Предохранитель обслуживания остаётся: не более 16 **новых обходов** на чанк за проход; ещё не проверенные отдельные полости сверх бюджета консервативно считаются неэкранированными.

## 4. Облучение внутри

Раз в 20 тиков в общую входящую дозу добавляется **0.40 × сумма фактической эмиссии блоков в той же замкнутой полости**. Наблюдатель определяется по клетке глаз, чтобы плита/ступенька под ногами не стала точкой обхода из стены. Закрытая перегородка, признаваемая радиационной оболочкой, отделяет соседнюю комнату. Это ограниченная клеточная модель, не расчёт расстояния/угла/геометрии каждой грани модели блока.

- Учитываются реальные блоки, включая соседние в куче, без зависимости от источника их появления и без лимита «16 блоков» для этой дозы. Содержимое контейнеров в новый вклад **не входит**; инвентарь и чанк работают как раньше.
- Защита внешнего чанка не умножает внутреннюю дозу. Хазмат, абсорбция дозы и прочие прежние модификаторы применяются после сложения, как обычно.
- Открытая/слишком большая/неполностью загруженная полость не считается доказанным контуром: отдельного внутреннего вклада нет; обычный фон чанка продолжает действовать. Ограничения радиационного обхода — 2048 посещений и 32 блока по каждой оси; это **не** ограничения/whitelist чистой комнаты.
- Один блок радия = 9×75 = **675 mZt/с**, новый локальный вклад = **270 mZt/с до защиты**. Два блока — 540 mZt/с. Нулевой внешний фактор при этом не делает работу внутри безопасной.
- Новый вклад идёт в дозу игрока, а не напрямую в заражение чанка/предметов. Обслуживание фонового заражения и индекс поставленных источников не заменены новым сканированием мира.
- Строка «Чанк» дозиметра/телифона остаётся именно фоном чанка: внутри защищённой коробки он может быть низким одновременно с растущей дозой игрока. Формат этих приборов не изменён.
- `/gonzotech debug getdose` дополнен состоянием контура, внешним множителем и локальной дозой. Заодно исправлена печать `Component` вместо читаемого числа у списка источников.

3. Две соседние закрытые комнаты, 17+ источников в одной, открытие/закрытие двери, смена измерения с теми же координатами, выгрузка/загрузка чанков.
