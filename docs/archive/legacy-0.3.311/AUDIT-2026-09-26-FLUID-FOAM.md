# AUDIT-2026-09-26 — общая пенка поверхности (0.3.22)

**База:** `a0f02c6`, 0.3.21. Автор утвердил общий бюджет `round(7 + 1.32N)` и размер **0.8–2.0**. Цвета и поведение частиц менять не просил.

## Сделано

- Убран порционный спавн 5–10 пылинок из `ModFluidBlock.animateTick`. Теперь пеной управляет только клиентский `FluidFoamClient`, один раз за клиентский тик, независимо от случайного тика отдельных блоков.
- **Сохранён именно ванильный Dust:** прежние шесть цветов из `ModFluidBlock.Kind`, спрайты, случайные оттенки, движение/затухание/физика и зависимость времени жизни от масштаба. Нового типа частицы, текстуры или ручного таймера жизни нет. Через `ParticleEngine.createParticle` получаем её настоящий handle, `isAlive()` и `getLifetime()`.
- Размер равномерно выбирается в **0.8…2.0**. Больший размер влияет на жизнь штатным способом Dust; контроллер реже восполняет долгоживущие частицы, а не накапливает их поверх бюджета.
- Пруд — четыре-связная открытая поверхность **одного Kind на одном block Y**. Источник и течение объединяются; различная высота FluidState внутри клетки не разделяет их. Диагонали, другие жидкости и ступени на другом block Y — разные участки. Граница чанка сама по себе не разделяет пруд.
- **N — число открытых клеток поверхности**, не глубина/объём. N=1/4/9/16/25/100 → целевое количество одновременно живых частиц 8/12/19/28/40/139. N=0 → 0.
- Каждое появление выбирает равновероятно клетку пруда и случайные X/Z внутри неё. Y = `blockY + FluidState.getHeight + random*[0,0.05)`, входная скорость остаётся **(0,0.015,0)**. Это появление на поверхности, не приклеивание к ней на всю жизнь; наклонный меш по углам не интерполируется, как и раньше.
- Жидкость сверху или сплошная нижняя опорная грань блока-крышки исключают клетку. Перед каждым появлением заново проверяются жидкость, тип, крышка, дистанция и загруженность.
- Общий бюджет заполняется постепенно (не залпом), смерти частиц распределяют следующие появления во времени. При объединении/разделении прудов существующие частицы привязываются по исходной клетке, не создаются повторно. При уменьшении бюджета лишние доживают; над исчезнувшей жидкостью новых нет.

## Ограничения и производительность

- Вместо новых хуков изменений мира — **непрерывное ограниченное пересканирование** ближней области с двойным буфером: до 512 проверяемых позиций за клиентский тик, по 16 блоков горизонтально и 8 вертикально от наблюдателя (33×17×33). Для жидкости дополнительно читается блок сверху. Незагруженные чанки не запрашиваются на загрузку.
- Полный проход — 37 тиков (около 1.85 с при 20 клиентских тиках/с). Публикуется только законченный проход, не отдельные куски с новым «+7». Первое обнаружение занимает один проход; изменение геометрии может отражаться до двух проходов. Выбранная точка спавна проверяется немедленно даже при устаревшем снимке.
- Для озера за границей области/загрузки N — **только обнаруженная местная поверхность**, не глобальный размер невидимого озера. Фрагменты, соединение которых находится вне области, могут временно считаться отдельными локальными участками. Абсолютный бюджет — **512** живых частиц и **64** попытки появления за тик на весь эффект; бюджеты разных прудов пропорционально сокращаются при превышении лимита.
- Настройки Minecraft: «Все» — полный бюджет, «Уменьшено» — половина, «Минимально» — пена выключена. Прямой вызов фабрики частиц обходит стандартное прореживание LevelRenderer, поэтому настройка применяется здесь явно, один раз, без бесконечных повторных попыток.
- Пауза останавливает контроллер; смена мира/измерения, большое перемещение и выключение эффекта очищают только его собственные частицы. Вытеснение/очистка ParticleEngine не оставляет вечные занятые места: handle ограничен его исходной продолжительностью жизни +2 тика на порядок обновления. При перегрузке общего движка фактически видимых частиц может быть меньше цели.
- Серверный `entityInside`, токсичность/эффекты погружения, цвета жидкостей, текстуры/туман и радиационные партиклы **не изменены**. Серверных пакетов или обращений к клиентским классам из блока жидкости не добавлено.
