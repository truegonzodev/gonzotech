# Жизненный цикл формы реактора I поколения — 0.3.235

Дата: 17.10.2026. Патч исправляет именно событийный жизненный цикл формы из 0.3.234; содержимое shell/interior whitelist, границы 4–16, узлы, визуалы и registry ID не меняются. Полный структурный контракт, пути и результаты проверки текстур остаются в [`REACTOR-STRUCTURE-0.3.234.md`](REACTOR-STRUCTURE-0.3.234.md).

## Правила событий

| Событие | Сформированный реактор | Несформированная геометрия |
|---|---|---|
| Размещение блока внутри объёма | Проверяется сохранённый куб; при нарушении whitelist/оболочки форма снимается. | Выполняется попытка формирования только если свежее размещение лежит внутри проверенного куба и весь куб валиден. |
| Размещение снаружи сохранённых bounds | Игнорируется: новое соседнее casing не расширяет shell и не запускает новое вычисление bounds. | Само по себе не формирует реактор, даже если неподалёку уже есть правильная геометрия. |
| Удаление/поломка участника | Позиция проверяется как воздух внутри сохранённого объёма; при нарушении валидности снимаются `formed`-визуал и сохранённое состояние панели. | Не запускает попытку сборки. |
| Загрузка панели / диагностика | Сохранённые bounds заново валидируются; если нужные чанки не загружены, проверка откладывается без force-load. | Автоматического формирования нет. Диагностика сообщает, что геометрия корректна, но для сборки нужно разместить блок внутри неё. |

## Реализация

- Bounds панели (`StructureMin` / `StructureMax`) — источник правды для уже сформированной структуры. Повторная проверка использует `validateBox` на этих exact bounds, не запускает shell flood-fill и не вычисляет новый bounding box.
- `MEMBER_INDEX` — transient-индекс текущего загруженного уровня: каждая клетка сохранённого объёма указывает на контроллер. Он строится после успешной проверки/восстановления, используется для адресной проверки placement/break и удаляется при unload панели или invalidation.
- `PANEL_POSITIONS` остаётся индексом загруженных панелей: он ищет ближайшего кандидата для формирования после placement и служит fallback для сформированного контроллера до восстановления `MEMBER_INDEX`. Для formed-контроллера дополнительно проверяется `panel.contains(changed)`, поэтому наружное изменение не затрагивает сохранённый snapshot.
- Shell flood-fill кандидата не проходит через клетки, уже принадлежащие индексированному сформированному реактору. Это не даёт соседней несформированной оболочке поглотить bounds действующей структуры.
- `partRemoved` выполняет только `invalidateAt`; попытка `tryFormFromPlacement` находится только на пути размещения. Диагностика несформированной панели может проверить геометрию, но сама не меняет её состояние.
- Событие размещения пропускается, если оно отменено. Callbacks блоков casing, панели и чехла сохранены.
