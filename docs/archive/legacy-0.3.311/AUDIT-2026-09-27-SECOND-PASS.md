## Реализовано

### Ложная смерть не переносится через выход из мира

Автор воспроизвёл перенос между разными мирами в игре и разрешил пожертвовать сохранением
между перезаходами. Добавлен один `ClientPlayerNetworkEvent.LoggingOut`-обработчик в уже
зарегистрированный клиентский класс: очищает иллюзию/причину, фиксацию камеры, latch ЛКМ,
кадр анимации и `PsycheNetwork.CLIENT_DATA`. **Никаких карт миров, UUID-кэшей или сохранений.**
На logout не вызываются `grabMouse/releaseMouse`: переходом в меню владеет ваниль.
Перезаход в тот же мир тоже очищает иллюзию. F1-исправление 0.3.27 сохранено.

### Удалено чтение прозрачности PNG

Удалён `GuiMask.java`, поле маски, её построение в init, скан пикселей в `clipRect` и cache.
Порядок слоёв остался: фон → шкалы → передний PNG → предметы/тултипы.
Координаты/размеры машин не менялись. **Scissor для доли заполнения самой шкалы остаётся:**
он нужен, чтобы тайлы 16×16 рисовались только в заданной Java-области, а не целыми плитками
за её краями. Это не удаляемая PNG-маска. Поиск дырок/пороги альфы больше не участвуют.

### Ванильный учёт употребления

Общий маленький `ConsumptionAccounting.record` вызывается только после серверной проверки
успешного завершения, перед расходом/заменой ItemStack:
- `Stats.ITEM_USED`;
- `CriteriaTriggers.CONSUME_ITEM` с ещё не израсходованным предметом;
- `GameEvent.EAT/DRINK` по анимации предмета.

Подключён к DrinkItem (кружка/ведро/водка), CysteamineItem, PentacinItem, DtpaItem,
RadAbsorbentItem. Отказ ДТПА при активном курсе стоит **до** учёта; creative учитывается
по ванильному правилу, но предмет не расходует. Эффекты/дозы/тара/длительности не менялись.

**Оба сусла уже имеют vanilla Consumable** и получают тот же учёт от него; второй вызов
не добавлялся. Сверен путь `LivingEntity.completeUsingItem → ItemStack/Item.finishUsingItem →
Consumable.onConsume` и NeoForge hook `onItemUseFinish`. Общий LivingEntity не начисляет
за наши ручные реализации эти stats/criteria ещё раз.

### Бочка

- Собственный пресет **0.7 mZt/s на бочку** в RadSources: используется для предмета и
  поставленного блока общей радиационной системой. Без множителя металл-блока ×9.
- **2.3 mTx/s на бочку в инвентаре** в ItemToxicity, с обычными правилами этой системы.
  Новый радиус химического облака/контактный урон вокруг поставленной бочки не вводился.
- Добавлен точный 3×3 рецепт автора, выход 1, ID `gonzotech:waste_barrel`. Дополнительный
  гейт не придуман; доступность ограничена материалами (в том числе блоком плутония).
- Item Properties: `fireResistant`. Общий item-tag **`gonzotech:non_disposable`** содержит
  пока одну бочку; дальнейшие шлаки можно включать туда.
- Для выброшенных tagged-предметов: обработчик `EntityInvulnerabilityCheckEvent` защищает
  от damage-путей огня/лавы/кориума, взрыва, кактуса и других источников урона ItemEntity.
  Используется существующий NeoForge hook `isInvulnerableToBase`, без нового mixin.
- `ItemExpireEvent` при первом истечении времени включает vanilla unlimited lifetime:
  оставить бочку на 5 минут не является способом удаления отходов. Нет ежетикового
  сканирования мира и нет бесконечного продления lifespan с переполнением short.
- Powered-ветка отсеивателя проверяет тег **до изъятия из источника**: бочка остаётся в
  контейнере/буфере, не списывает бюджет. Следующие обычные предметы продолжают удаляться.
  Незапитанный reject-маршрут и совпавшая pass-ветка по-прежнему перевозят бочку.
  **Исправление 0.3.29:** формулировка «обход через I» была ошибочной — первый тир вообще
  не должен удалять. Проверка redstone перенесена из базового класса в II; I игнорирует сигнал.

**Границы:** это защита выброшенного предмета, не неразрушимый поставленный блок. Нет
перехвата административного удаления, прямого `discard` чужим модом, удаления мира или
падения в void (не damage-путь обычного ItemEntity). Намеренно не подменяется глобальный
Entity.remove, иначе ломались бы подбор/слияние стаков и команды администратора.

Уже поставленные в старом мире бочки, которые не попали в placed-registry до появления
пресета, следует поднять и поставить заново для проверки фона. Генератор будущих структур
должен регистрировать радиоисточники; полный скан всех старых чанков не добавлен.

## Цепочки ресурсов

Выделены все найденные машинные пути, отдельный крафт+лут слизи для Ra и условный лут
обломков для Pb. Разбор включает реальные probabilities, входы block/raw, гейт II,
расходы ЦФ, фактические JSON генерации и потребителей. Не обещает добычу блоков, для
которых есть только будущий лут структур. Самородки/слитки/пыль не объявлены самостоятельным
источником только из-за конверсий. Подробнее — в отдельном отчёте выше.

Важные выводы: Ra доступен и без ЦФ через слизь; Bi — узкая ветка U/Th; Pb можно получить
без радиоактивного сырья; литий уже массово получаем, но пока без отдельной полезной цепи.
В генерации uniform, а не обещанный названием поля bestY пик. В сплавах отдельно учтено
соотношение units (10 units/слиток vs 1/самородок), отличное от крафтовых 9 самородков.

## Исправление контракта 0.3.29

Проверкой исходников подтверждено: уже до патча бочки общий ItemScavengerBlock включал
удаление по redstone и для I. Это не краш и не новое разрешение 0.3.28, а прежняя ошибка
разделения функций по тирам. Теперь I всегда маршрутизирует reject-поток; II при сигнале
удаляет обычные предметы, не изымая защищённые. Без сигнала II маршрутизирует как раньше.
Тест drainContainer дополнен матрицей tier I/II × redstone OFF/ON × matched/rejected ×
protected/ordinary × источник/буфер с вызовом фактических isPowered обоих классов.

Проверка 0.3.29: 9612 production-body checks на API-заглушках прошли; ресурсы,
inventory, naming/doc-links/whitespace — без ошибок. Gradle compileJava остановился
до компиляции на TLS-загрузке wrapper. Игровой запуск не выполнялся.
