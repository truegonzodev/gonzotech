### PERF-001 — предметная логистика, безопасность автоматизации, бюджеты и lifecycle

**Статус: в процессе — валидация, исследование и согласование методов.** Все14пунктов автора входят в одну текущую задачу. Ничто из нижеследующего ещё не исправлено этим шагом. Авторские серверные пробы — предоставленные автором доказательства, не самостоятельно воспроизведённые здесь тесты. Проблемы/риски по исходнику и отсутствие TPS-замера отмечаются отдельно. «Предложение» не превращается в единственно разрешённый метод.

**Цикл:** (1) зарегистрировать → (2) проверить причину, API/связи, обсудить альтернативы и выбрать лечение с регрессией → (3) применить ограниченный патч → (4) повторять2/3 по результатам тестов/авторской игры. Не закрывать по одному source-пину; новое лечение не должно ломать суммы, loaded-границы, защиту, радиационные sidecars и протокол end.

#### 1. Предметная труба → двойной сундук

**Источник:** авторская серверная проба: новая wrapper, перенос0, предмет остался у источника. Source сверка: ItemRouting.sinkLive действительно сравнивает `containerAt(...) == sink.container`.
**Кандидат лечения:** стабильная идентичность физических владельцев (обе половины/позиции/сущность), повторное разрешение живого контейнера при commit; не сравнивать только координату, чтобы не принять заменённый BE. Проверить новый wrapper того же сундука, разделение/замену половины, обычный BE и вагонетку. Взаимосвязь с14; метод ещё не применён.

#### 2. Одноштучные карты Плотника и автоматизация

**Источник:** авторская серверная проба16карт в A. Source: CardSlot=1 только в menu; canPlaceItem/ThroughFace разрешают карты, ItemRouting.tryPlace берёт item/container max, не per-slot1.
**Кандидат лечения:** единый серверный per-slot capacity для обоих слотов A/B, всех insert/merge/adapters и simulate/остатка, не только GUI. Проверить трубы/воронки/стандартный handler, пустой/занятый слот, карты без потери остатка. Не лечить общий дюп срезанием count; формат legacy не менять.

#### 3. Усечённый BFS и большие сети

**Источник:** авторская проба budget2→visited3; source: sentinel2 затирается `visitedOut[0]=visited.size()`. Частичный результат может попасть в полный кэш; число2 также конфликтует с настоящим количеством посещений.
**Выбранное направление автора:** отдельно complete/visited/result; для действительно больших сетей продолжение между тиками. Уточнить структуру per-level очереди/справедливость; сохранять frontier, но сбрасывать при изменении топологии/выгрузке. Регрессии budget1/2/граница/несколько стартов/большая сеть: дальние sinks в итоге находятся, частичный результат не считается полным. Начинать заново каждый тик недостаточно.

#### 4. Подъехавшая контейнер-сущность

**Источник:** по коду; cache hit использует version equal **OR** age≤TTL. Блоки не менялись — пустой список не стареет.
**Кандидат лечения:** валидная версия **и** ограниченный возраст, дополненный живым разрешением entity endpoint. TTL/текущий throughput попутно не менять; не полагаться только на setBlock. Проба: пустой поиск→вагонетка приехала без block edit→находится; отъезд/замена также не дают ghost sink.

#### 5. Ограниченная загрузка чанков предметными трубами

**Решение автора:** загрузка разрешена только для чанка с источником/приёмником этой трубы; фильтр и сепаратор не endpoints; транзитная линия инертна, километры труб не должны запускать цепь загрузок. Это не новый глобальный chunkloader и не расширение прогрева Плотника5×5.
**Сверка:** getBlockState в BFS/live-проверке и HopperBlockEntity.getContainerAt — пути без явных loaded guards. Нужны инструментированные load-count тесты. **Блокер метода:** как узнавать endpoint в ещё не загруженном чанке; согласовать adjacent-only против реестра ранее известных endpoints, ticket lifetime/границы, отсутствие цепного пробуждения. Не обещать найти неизвестный дальний endpoint без обхода.

#### 6. Дорогие кнопки и begin/end Fence

**Источник:** по коду; PlotnickButtonPayload проверяет menu/access, но нет rate gate; тяжёлые кнопки входят в синхронные сканы. Fence.begin не запоминает активную sequence до ACK на end и повторно вызывает CreativeRadiationBridge.begin, где создаётся новый Session со stack.copy.
**Направление автора:** rate limit плюс бюджет тяжёлой работы Плотника, кэш результатов; полноценная последовательность Fence begin/end. **Кандидаты:** одна активная задача на BE с дедупликацией/отменой; per-player/menu sequence-state, допустимый end обрабатывается независимо от исчерпания begin-бюджета. Нужны согласование повторных кнопок и лимитов, защита stop/close/disconnect, tests nested inventory/duplicate/reordered begin/end без потери дозы/ACK.

#### 7. Равновесие аккумулятор I→II

**Источник:** source подтверждает отдельные branches I/III, II проходит через общий GtuSink; II→I имеет half-difference gate.
**Кандидат лечения:** симметричный branch II перед generic sink, прежние абсолютные запасы/milli и половина положительной разницы, не проценты capacity. Проверить I<II, I=II, I>II, прямой/проводной маршрут, потери отправителя и отсутствие перелёта/пинг-понга.

#### 8. Суммарный приём аккумуляторов I/II за тик

**Источник:** оба receiveGtu каждый вызов ограничивают полным intake, общего счётчика нет. III уже использует TickEnergyStorage.
**Направление автора:** перенести принцип per-gameTime aggregate budget, сохранив **все нынешние числа**, loss/NBT/capacity и simulate read-only. Не переносить целиком конечную модель III на старый GtBuffer. Пробы нескольких источников/сторон, повторы simulate, следующий тик, unload/reload; accepted списывается только при реальном commit.

#### 9. Настоящая ownerless WorldGuard-интеграция

**Источник:** авторская API-сверка и независимая сверка EngineHub WG7/WE upstream: RegionContainer.get(WorldEdit World), RegionManager.getApplicableRegions(BlockVector3), BukkitAdapter.adapt(Bukkit World). Текущие getRegions/getFlagState и прямой Bukkit world не соответствуют стандартному WG7. PLACE/BREAK сейчас проверяют разные наборы и отсутствие DENY вместо всех трёх разрешений.
**Требование автора:** без владельца/ближайшего игрока; затронутая клетка; все piston_allowed/block_place/block_break разрешены; настоящий адаптер и проверка работоспособности. **Блокеры:** конкретный hybrid/bridge, mapping ServerLevel→WorldEdit world, реальные flag IDs/семантика piston, поведение без WG/с поломанным bridge/без региона/с unset. Не заявлять защиту на реальном сервере без интеграционной проверки. Никакого молчаливого actor fallback как лечения.

#### 10. Очереди и повторный сбор слоя

**Источник:** старые#39/#40; в коде remove(0) для build/dismantle/TNT, отдельной готовности слоя недостаточно считать сделанной. TPS не замерен.
**Предложения, не фиксированный рецепт:** deque либо cursor без сдвига списка; отметка обработанного слоя с корректной инвалидацией. Проверить сериализацию/перезаход, новые блоки в слое, start/stop/packUp и сброс фаз. Второй приоритет после сетевых ошибок; не полный редизайн Плотника.

#### 11. setVirtual — остаток N5

**Источник:** source подтверждает возврат старого типа через insert/dump внутри setter; доступный игроку текущий дюп **не установлен**.
**Требование автора:** setItem/setVirtual только заменяют; возврат вытесненного отдельной явной операцией. Проверить всех callers/ownership, воронку rollback, virtual replacement другим типом/пустым/тем же типом и inventory+ground conservation. Не объявлять исправление подтверждённого игрового дюпа и не делать legacy migration.

#### 12. Контуры, общий room snapshot, облегчённые транзакции

**Источник:** старые#33/#36; source: любой ChunkEvent.Load/Unload делает CACHE.remove(level), insideDose собирается для каждого observer, MenuDoseTransaction/Creative bridge копируют stacks. Реальный предел TPS не измерен.
**Предложения для брейншторма:** адресная invalidation по зависимостям; общий read-only физический snapshot с исключением собственного inventory конкретного observer; облегчённые transaction snapshots. Сохранить живость меняющегося содержимого, identity-дедуп, ender exclusion, mutation-fence provenance, дозы/count/copyTree и loaded bounds. TTL без инвалидирования содержимого недостаточен. Радиационный баланс/формулы **не менять**.

#### 13. Проверка общих участков маршрутов

**Источник:** source: liveSinks для каждой source face вызывает sinkLive и обходит каждый сохранённый path, независимо от BFS-бюджета.
**Предложение:** проверка shared segments один раз в тик/ключ world revision либо локальные зависимости вместо повторного полного обхода. Метод ещё не выбран; world edit в том же тике должен снять stamp. Поломка/замена трубы/закрытая грань/неизвестный чанк всегда отменяют передачу; непроверенный маршрут не возвращать.

#### 14. Lifecycle кэша ItemRouting

**Источник:** values CachedSinks→Sink→Container могут держать world; WeakHashMap<Level,...> сам по себе недостаточен. Явная очистка ItemRouting на unload/stop в осмотренном файле отсутствует; измеренного heap leak здесь нет.
**Предложения:** хранить адреса+проверяемую identity вместо долгоживущих BE refs; явные owner/chunk/level/server cleanup. Согласовать общую модель с1/3/4/13, чистить pending frontier/проверочные stamps/бюджеты, не только TOPO_CACHE. Проверить два мира, unload/reload/stop, переустановку в ту же координату, entity removal; weak-key не считать достаточным тестом освобождения.
