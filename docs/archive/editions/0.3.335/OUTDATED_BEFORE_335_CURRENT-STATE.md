### HUD-NODE1 — Мигает счётчик сшитых узлов

**Статус: текущая задача, зарегистрирована; не исправлено.** По наблюдению автора строка «сшито узлов: 12» пропадает/появляется примерно раз в секунду. Уточнение автора: **«Любая сшитая группа»**, не только узлы реактора. Число12 — пример, не отдельный лимит.

**Требование/приёмка:** при неизменной группе и наведении строка/число остаются стабильными между обновлениями; действительное изменение состава отражается корректно. Проверить разные типы/тиры групп, смену цели/типа, распад/пересшивку и задержанные ответы, без переноса счётчика старой группы на новую. Не лечить замороженным числом, фиктивной единицей или постоянным скрытием строки.

**Основание для диагностики, не доказанная причина:** WrenchHud рисует clumpSize только из достаточно свежего FlowEntry (>0); REQUEST_INTERVAL=5 и FLOW_STALE_TICKS=15. Разделить жизненный цикл счётчика топологии и свежесть flow-метрик, проверить ответы/нулевые промежуточные значения и инвалидирование. Само мигание не доказывает полный пересчёт сети каждую секунду. Существующую периодическую проверку не требуется отменять ради визуального исправления. Не активировать D-PIPE2/новую оптимизацию всей сети. [AUDIO_VISUAL](AUDIO_VISUAL.md#hud-node1), [CAPABILITIES](CAPABILITIES.md#reactor-review334).

### REACT-VAL1 — Режим встроенного узла ошибочно ломает валидность реактора

**Статус: текущая задача, зарегистрирована; не исправлено.** Переключение режима узла в обшивке расформировывает реактор; возврат в AUTO не помогает. По наблюдению автора лишь break/place однажды переключённого узла позволяет снова сформировать реактор.

**Утверждённое требование:** режим standalone-узла не должен определять допустимость встроенного реакторного порта. В сформированном реакторе это **порт**, не обычный сетевой узел. Смена режима при неизменной допустимой геометрии/типе блока не расформировывает реактор и не оставляет его неформируемым; проверить также восстановление уже испорченного состояния без принудительного break/place. Сверить портовый I/O, bounds/index, water/heat/universal варианты, несколько портов и обычные узлы вне реактора. Не отменять реальную проверку оболочки/loaded-состояния и не отключать CRIT-1 guard, чтобы скрыть распад.

**Без перебалансировки:** текущий REACTOR_GTH_PER_PORT_MILLI =16_364×MILLI, то есть **16 364 GTH/т на вывод**, а не новый лимит10К. gthPortLimit — потолок реактора; подключённые трубы сохраняют свои ограничения. Ни этот потолок, ни общий ресурс/буферы, ни standalone-режимы всей сети не переписываются под видом валидации. [REACTORS](REACTORS.md#reactor-review334), [MULTIBLOCK](MULTIBLOCK.md#reactor-review334), [CAPABILITIES](CAPABILITIES.md#reactor-review334).

### REACT-VAL2 — После возврата обшивки поршнем formed расходится с действительной валидностью

**Статус: текущая задача, зарегистрирована; не исправлено.** Поршень вытягивает блок оболочки — реактор расформировывается. При возврате блока текстура становится formed, но попытка открыть GUI сообщает невалидность; только ручной break/place восстанавливает работоспособность. По сообщению автора, аналогичный поршневой сценарий у парогенератора/турбины работает.

**Требование/приёмка:** после завершённого обратного движения поршня и восстановления допустимой оболочки ранее собранный реактор снова действительно валиден без ручной установки блока. Согласованы текстура/formed панели, bounds/member index, живые порты и открываемость нового GUI, а не только декоративный флаг. Пролом/недопустимая оболочка остаются невалидными; недоступная зона не считается валидной. При настоящем распаде старое GUI по принятому CRIT-1 закрывается и после восстановления не перенаправляется молча на новые владельцы. Тепло/топливо/вода сохраняются без дюпа, обнуления или доступа через устаревшие endpoints.

Проверить выдвижение/возврат и повторы поршня, реальные промежуточные moving-блоки, разрушение вместо возврата, ручной break/place и соседнюю регрессию парогенератора/турбины. Это точечное расширение прежнего placement-only контракта **для возврата обшивки ранее собранного реактора**; не разрешение первичной автосборки от любого chunk-load/периодического глобального сканирования или переписывания всех мультиблоков. Источник события и момент безопасной повторной валидации ещё нужно исследовать. [MULTIBLOCK](MULTIBLOCK.md#reactor-review334), [REACTORS](REACTORS.md#reactor-review334), [MACHINES](MACHINES.md#reactor-review334).
