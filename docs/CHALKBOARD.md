# Доска резонанса: техническое устройство и подсказки

Срез кода: **0.3.311**, база `26e2a31`, сверка 27.10.2026. Книга/страницы/избранное — [SCHOLAR_NOTES](SCHOLAR_NOTES.md); таблица открытий и гейты — [PROGRESSION](PROGRESSION.md).

## Блок, UI и владельцы состояния

- `chalkboard/ChalkboardBlock` — DirectionalBlock, шесть направлений FACING; установка по clickedFace. `useWithoutItem` открывает клиентский экран через `ChalkboardClientHandler`. Собственного BE-инвентаря доски нет: прогресс не принадлежит поставленному блоку и не становится общим для всех подошедших игроков.
- `client/ResonanceScreen` — редактирование формулы, лоток величин, рисунок, показ подсказки. Клиентское равенство/видимый результат не даёт права получить награду.
- `core/ChalkboardWorldData` — SavedData `gonzotech_chalkboard_puzzles`, seed мира и кэш задач по index; первые 16 генерируются при инициализации, далее infinite-задачи по запросу. `stableIds` делает ID дерева зависимыми от пути/стадии, а не локального счётчика процесса; сохранённый черновик узнаваем после рестарта.
- `progress/PlayerChalkboardProgress`, attachment `ModAttachments.CHALKBOARD_PROGRESS` — currentDiscoveryIndex, открытые recipe tiers/secret quantities, формулы по discovery index, рисунки и непрерывный globalDrawingJson. В том же attachment находятся noteFlags/favoriteNotes/флаг выдачи книги, но их API и экран описаны отдельно.
- `core/Expr`, `Quantities`/`Quantity`, `DimVec`, `Evaluator`, `GameSolver`, `DiscoveryDef` — AST, величины/размерности, анализ и генерация. `SelfTest` — headless вход для ядра, не игровой тест UI.

## Серверная цепочка решения

1. `ChalkboardNetwork` получает C2S запрос синхронизации и отдаёт задачу текущей стадии, допустимый лоток и проверенный сохранённый черновик. Network handlers выполняются через enqueueWork; PayloadThrottle отдельно ограничивает sync/presence/save/submit.
2. `SaveExprPayload` — только черновик. `Serde` ограничивает JSON (32×1024 UTF-16 символов), глубину дерева 48 и количество узлов 192; сетевые codecs имеют собственные byte-границы. Рисунок ограничен отдельно (256×1024). Название `MAX_EXPR_JSON_BYTES` не отменяет различия bytes и chars.
3. `ChalkboardSubmissionValidator.validateDraft` проверяет принадлежность AST серверному skeleton, ID/locked-slots/операторы и доступность подставленных quantities. Нельзя прислать произвольное верное уравнение вместо выданной задачи.
4. `SubmitPayload` принимается только для текущего index игрока; `validateClaim` повторяет проверку черновика и математического результата через Evaluator. Stale/future index не награждается. Creative/op имеют отдельное разрешение server-side на весь лоток (`canUseQuantity`), а не обход проверки задачи.
5. Только после accepted: secret unlocks, advanceDiscovery, сохранение attachment, награда и свежий sync. Index 0…15 соответствует discovery 1…16; далее infinite mode (опыт). Решить задачу/получить discovery-предмет не равно активировать recipe tier — активация и достижения описаны в PROGRESSION.

Наличие физической доски для естественной подсказки проверяется отдельно. Не выводить из открытия экрана универсальную гарантию distance/ownership-проверки каждого C2S payload: контракт конкретного handler нужно читать в коде.

## Интеграция подсказок

Источник истины — `chalkboard/ResonanceClue`, `core/psyche/AlcoholEffects` и `AlcoholDose`.

- `giveNatural` используется выпитыми напитками: пивная кружка / ведро / водка имеют соответственно 1% / 3% / 9% шанс. Нужна ближайшая **загруженная** доска в настоящей сфере радиуса 16 блоков; угол куба поиска не считается близостью. При отсутствии доски/результата нет сообщения об успешной подсказке.
- `/gonzotech debug clue` зовёт `give`; debug работает и без доски. Револьвер — отложенный источник (D-PSY4), не реализованная интеграция.
- Выбирается случайная quantity из `sampleSolution` **текущей серверной задачи**, не из пользовательского черновика. Target исключён: это цель уравнения, не разрешённая плитка лотка.
- Если quantity ещё закрыта, сервер добавляет её в unlockedSecretQuantities, сохраняет прогресс, шлёт `CluePayload` и полный sync. Это постоянное разрешение игрока; одной клиентской подсветки недостаточно для принятия решения.
- `ChalkboardClueClient` держит hintedId/AVAILABLE/pinned/version. `ResonanceScreen` обводит плитку белым и ставит первой до закрытия доски; первое использование снимает обводку. Снятие pin не отменяет серверное открытие quantity.
- У найденной доски появляются 12 happy_villager particles. Это визуальное подтверждение, не перенос прогресса в блок.
- **Дополнительной цены подсказки нет.** Эффекты уже выпитого напитка (психика/зависимость/еда и т.д.) применяет AlcoholEffects независимо. Не вводить новый стресс/дозу за выдачу clue. Связанная механика — [PSYCHE](PSYCHE.md).

## Изменение и проверки

При изменении задачи проверять генерацию, stableIds, Serde, server validation, sync и сохранённый черновик совместно. При изменении источника clue — AlcoholEffects/ResonanceClue, разрешение quantity, клиентскую рамку и отказ без доски. Не смешивать это с гейтами страниц книги.

`./gradlew selfTest` запускает core SelfTest; `audit/alcohol_test.py` и `audit/qol_batch_test.py` проверяют части алкогольного/clue-контракта, не всю игровую доску. Команды и границы доказательств — [AUDIT](AUDIT.md). UI, перезаход, смена мира и награда проверяются отдельно в игре.
