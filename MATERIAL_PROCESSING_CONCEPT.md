# Концепт V1: дробилка, центрифуга и задел для завода сплавов

**Статус:** согласованный текстовый концепт перед реализацией.

**Область:** первый индустриальный путь переработки 26 существующих руд и источники чистых вторичных металлов.

**Не входит в этот patch:** конкретные рецепты корпусов машин, энергобаланс, GUI, recipe-book unlocks, готовая цепочка восстановления оксидов и полный рецепт завода сплавов. Эти вещи должны быть отдельным следующим согласованием, а не неявно придуманными в коде.

Документ фиксирует уже принятые решения и отдельно перечисляет данные, которых пока нет. Незаполненные места намеренно не заменяются выдуманными шансами или «химией на глаз».

---

## 1. Цель системы

Существующий рудный пласт остаётся рабочим и не переделывается. Простая переплавка в печи продолжает быть коротким ранним путём, а индустриальная переработка добавляет:

- ценность добытому рудному **блоку**;
- контролируемое получение `raw_*` сырья;
- основные обогащённые порошки/концентраты;
- вторичные чистые металлы без dedicated ore;
- фундамент для будущего завода сплавов.

Итоговая идея:

```text
22 обычные рудные блоки
        │
        ▼
   ДРОБИЛКА
        │  1× сырьё гарантированно
        │  + шанс на ещё 1× такое же сырьё
        │  + шанс на побочку, зависящую от host-породы
        ▼
 raw_<материал>
        │
        ▼
 ЦФ1УР
        │  1× чистая металлическая пыль гарантированно
        │  + до трёх независимых побочных результатов
        ▼
 чистые металлические пыли
        │
        ├─ переплавка → слиток
        ├─ завод сплавов → сплав
        └─ ЦФ2УР / ЦФ3УР → более глубокая переработка,
                            соли/оксиды и старшие побочки
```

Параллельно существуют четыре специальные ресурса «как лазурит»:

```text
сера, марганец, йод, ртуть
```

Они не являются входом основной промышленной таблицы V1 и не получают стандартные dust/nugget формы. При добыче их рудный блок даёт опыт и минерал-сырьё, а не сам блок. Исключение из nugget-правила — существующий ртутный самородок.

## 2. Что остаётся без изменения

### 2.1. Простая печь — ранний путь

Все существующие ванильные рецепты переплавки модовых руд и `raw_*` сырья остаются:

```text
руда / сырьё → 1 слиток
```

У простой печи нет гарантированных минеральных побочек и нет удвоения результата. Это дешёвый и понятный путь для ранней игры.

Центрифуга I становится выгодной альтернативой, но не ломает уже закрытый рудный пласт и не заставляет переделывать все старые recipes.

### 2.2. Свинец от плавки железа

Существующая механика тоже остаётся:

```text
получение iron ingot при плавке → 5% шанс на 1 lead ingot
```

Она работает как ранний удачный источник свинца. Центрифуга не отменяет его, а создаёт полноценный промышленный путь через барит, сфалерит, акантит, уранинит и торианит.

Текущая реализация проверяет именно получившийся `minecraft:iron_ingot`; поэтому эффект существует и в ванильных печах, и в текущих модовых печах. Это следует сохранить, пока не будет отдельного решения о ребалансе.

### 2.3. Четыре «лазуритных» минерала

| Ресурс | Текущее добываемое сырьё | Опыт при добыче | Стандартная пыль | Стандартный самородок |
|---|---|---:|---|---|
| Сера | `raw_sulfur` | да | нет | нет |
| Марганец | `raw_manganese` | да | нет | нет |
| Йод | `raw_iodine` | да | нет | нет |
| Ртуть | `raw_mercury` | да | нет | есть |

Они намеренно не смешиваются с таблицей центрифуги как «ещё четыре обычные руды».

**Важное уточнение для таблицы:** где раньше было написано «марганцевая пыль» как побочный результат, в реализации это означает **один `raw_manganese`**, то есть минерал, который и так выпадает из марганцевой руды. Новый `manganese_dust` для этого создавать не требуется.

## 3. Термины и реальные предметы текущего проекта

| Термин в концепте | Значение |
|---|---|
| **Рудный блок** | Один из существующих block item вариантов: stone, deepslate, nether или calcite host. Именно он ценен для дробилки. |
| **Сырьё / raw** | Предмет `raw_<id>`; для кальция это `raw_calcite`. Получается из дробилки обычной руды или напрямую у четырёх специальных минералов. |
| **Основной обогащённый продукт** | Один порошок/концентрат, который центрифуга выдаёт гарантированно. В рабочей таблице он пока назван химической формой или металлической пылью. |
| **Металлическая пыль** | Чистая пыль металла; естественный вход будущего завода сплавов и, где уместно, печи. |
| **Соль / оксид / концентрат** | Не чистый металл. Для них в будущем нужна отдельная processing rule: плавка, восстановление или иной заданный рецепт. |
| **Побочка** | Дополнительный stack, бросаемый независимым шансом. Не заменяет основной выход. |
| **Host-побочка дробилки** | Дроп, определяемый породой рудного блока, а не металлом в самой руде. |

### 3.1. Текущее различие между именами минералов и внутренними ID

В игре исторически блоки названы по металлу (`aluminum_ore`, `zinc_ore` и т. п.), а таблица использует правильные геологические названия минералов. Это не повод переименовывать уже готовые блоки/loot/worldgen.

Нужно использовать следующую логику в интерфейсе и рецептах центрифуги:

```text
Боксит             = aluminum ore / raw_aluminum
Сфалерит           = zinc ore / raw_zinc
Касситерит         = tin ore / raw_tin
Поллуцит           = cesium ore / raw_cesium
...
```

То есть минералогическое название может быть видно игроку в экранной подсказке/рецепте, а стабильный внутренний item ID остаётся прежним.

## 4. Дробилка

### 4.1. Назначение

Дробилка не повторяет центрифугу и не должна сразу создавать чистую металлическую пыль.

Её роль:

```text
рудный блок → сырьё для дальнейшего обогащения
```

Это сознательно делает сам добытый блок ценнее простого `raw_*` предмета. Игрок выбирает:

- быстро переплавить имеющееся сырьё/руду в один слиток;
- сохранить и переработать рудный блок, чтобы получить сырьё с шансом на удвоение и host-побочку, затем отправить сырьё в центрифугу; при необходимости сам блок также можно подать в ЦФ1УР без дополнительного бонуса.

### 4.2. Входы

Дробилка принимает **только рудные блоки**, не `raw_*` сырьё:

- все host-варианты 22 обычных руд;
- stone/deepslate/nether/calcite варианты там, где они существуют;
- в частности, `calcite_calcium_ore` — допустимый кальцитовый host-вариант.

Четыре специальные «лазуритные» руды (`sulfur`, `manganese`, `iodine`, `mercury`) в эту V1-механику не входят: при добыче они уже превращаются в минерал и опыт, а блока для промышленного дробления обычным путём не оставляют.

### 4.3. Выходы одной операции

На один обработанный рудный блок:

| Выход | Количество | Вероятность | Источник правила |
|---|---:|---:|---|
| Основное сырьё | 1 | 100% | Определяется металлом руды. |
| Дополнительное такое же сырьё | 1 | требуется балансное число | Определяется металлом руды. |
| Host-побочка | 1 | требуется балансное число | Определяется только host-породой блока. |

Примеры основного сырья:

```text
aluminum_ore             → raw_aluminum
zinc_ore                 → raw_zinc
calcite_calcium_ore      → raw_calcite
nether_cobalt_ore        → raw_cobalt
```

### 4.4. Принятые ограничения дробилки

- Host-побочка **не зависит от руды**, иначе система смешает две разные идеи.
- Один и тот же рудный блок не должен одновременно быть входом в дробилку и автоматически превращаться в сырьё где-то ещё.
- Roll на дополнительное сырьё и roll на host-побочку должны быть независимыми.
- Если выходной inventory заблокирован, операция не должна уничтожать возможный результат. Машина ждёт места либо гарантированно резервирует output до запуска цикла.
- Дробилка должна иметь минимум три выходные позиции: основное сырьё, дополнительное сырьё и host-побочка. Возможен общий stackable output inventory, но нельзя терять результат из-за переполнения.

### 4.5. Данные, которые ещё нужно утвердить перед кодом дробилки

Пока **не заданы** и не должны быть угаданы в коде:

1. шанс второго `raw_*` предмета;
2. шанс host-побочки;
3. полный mapping host → тематический самородок/предмет:
   - stone host;
   - deepslate host;
   - nether host;
   - calcite host;
4. дроп-таблица дробления ванильных `granite`, `diorite` и `andesite`:
   - гарантированный выход;
   - каждая побочка;
   - шанс каждой побочки;
   - нужен ли отдельный output type, например gravel/rock powder.

Это единственные содержательные части дробилки, которые пока нельзя честно назвать implementation-ready.

## 5. Линейка центрифуг: общий принцип

Центрифуги — не одна машина с бесконечно разрастающейся таблицей, а уровни переработки одного минерала. Чем выше уровень, тем больше материальная отдача и тем больше промежуточных форм/возни.

| Уровень | Гарантированный основной выход | Дополнительный выход | Побочки | Роль |
|---|---|---|---|---|
| **ЦФ1УР** | 1× чистая металлическая пыль | нет | До 3 независимых, сниженных шансов | Первый полезный способ получать вторичные металлы. Простая и понятная переработка. |
| **ЦФ2УР** | 1× чистая металлическая пыль | 1× соль/оксид | Больше и/или ценнее, чем у ЦФ1УР | Углублённое обогащение: добавляет химическую ветку и повышает суммарную отдачу. |
| **ЦФ3УР** | 2× чистая металлическая пыль | определяется будущей таблицей | Крутые поздние побочки | Поздняя высокоэффективная переработка. |

В этом документе полностью фиксируется только **ЦФ1УР**. Для ЦФ2УР и ЦФ3УР заданы границы дизайна, но их шансы, рецепты, энергия и полный состав дропов не подменяются догадками.

## 6. Центрифуга первого уровня — ЦФ1УР

### 6.1. Назначение

ЦФ1УР — базовое промышленное обогащение. Она не создаёт оксиды, соли или концентраты: её гарантированный выход всегда один — **1 чистая металлическая пыль** соответствующего материала.

```text
1× сырьё raw_<материал> ИЛИ 1× соответствующий рудный блок
        ↓
1× <металл>_dust гарантированно
+ 0..3 независимые побочки
```

У ЦФ1УР нет удвоения главного ресурса. Её преимущество над печью — вторичные материалы и возможность переработать ценный рудный блок тем же результатом, а не прямое умножение основного металла.

### 6.2. Входы: сырьё и рудные блоки равноправны

Для каждой строки ЦФ1УР доступны два равнозначных вида входа:

1. соответствующий `raw_*` предмет;
2. любой существующий вариант рудного блока этого материала — stone, deepslate, nether или calcite, где такой host существует.

Они расходуются по курсу **1 вход → один и тот же результат**. У подачи рудного блока в ЦФ1УР нет дополнительного бонуса: его ценность раскрывает дробилка, а центрифуга лишь допускает прямую переработку для удобства.

Примеры:

```text
raw_aluminum / aluminum_ore                   → результат строки «Боксит»
raw_cobalt / deepslate_cobalt_ore             → результат строки «Кобальтин»
raw_cobalt / nether_cobalt_ore                → тот же результат строки «Кобальтин»
raw_calcite / calcite_calcium_ore             → результат строки «Кальцит»
raw_zirconium / deepslate_zirconium_ore       → результат строки «Циркон»
```

Четыре специальные «лазуритные» руды (`sulfur`, `manganese`, `iodine`, `mercury`) по-прежнему не получают recipes ЦФ1УР, пока не будет отдельной таблицы для них. Формулировка «raw или рудный блок» относится к 22 строкам ниже.

### 6.3. Формула шансов ЦФ1УР

Для каждой побочки берётся процент из прежней рабочей таблицы и применяется строго одна общая формула:

```text
новый шанс = (старый шанс × 0.90) − 0.5 процентного пункта
```

Пример, подтверждённый для стандарта:

```text
15.0% → (15.0 × 0.90) − 0.5 = 13.0%
```

Правило применяется ко **всем** побочкам, включая обновлённые ранее 15% неодима и 10% радия:

```text
15.0% неодима → 13.0% в ЦФ1УР
10.0% радия   →  8.5% в ЦФ1УР
```

Каждый итоговый шанс бросается независимо. За одну операцию возможны ноль, одна, две или все три побочки.

### 6.5. Output inventory ЦФ1УР

ЦФ1УР необходимы минимум четыре результата на операцию:

| Слот | Назначение |
|---|---|
| 1 | гарантированная металлическая пыль |
| 2 | побочка 1 |
| 3 | побочка 2 |
| 4 | побочка 3 |

Перед запуском операции машина обязана иметь возможность сохранить каждый выпавший результат. Нельзя молча удалить редкий радий, рений или неодим из-за заполненного output inventory.

## 7. Чистые вторичные металлы без dedicated ore

В центрифужной таблице шесть progression-critical чистых металлов не имеют собственной руды:

| Металл | Источник |
|---|---|
| Свинец | Барит, сфалерит, акантит, уранинит, торианит; дополнительно ранний шанс при плавке железа |
| Литий | Бура, поллуцит |
| Неодим | Циркон — **13.0% в ЦФ1УР**; reference-шанс 15% сохранён для ЦФ2УР-памятки |
| Висмут | Уранинит, торианит |
| Рений | Сфалерит |
| Радий | Уранинит, торианит — по **8.5% в ЦФ1УР**; reference-шанс 10% сохранён для ЦФ2УР-памятки |

### 7.1. Почему новые проценты выглядят здоровее

По текущей средней плотности worldgen циркон редок, а уранинит и торианит ещё реже. Исходные 5%/1% делали неодим и особенно радий практически невидимыми. Reference-значения были подняты до 15%/10%, а затем к ЦФ1УР применена единая понижающая формула; её итоговые 13.0%/8.5% всё ещё сохраняют заметный, но редкий характер этих металлов.

Иерархия остаётся такой:

```text
свинец / литий              — массовые вторичные материалы;
висмут / рений              — умеренно редкие;
неодим                      — редкий, но заметный;
радий                       — ядерный редкий компонент, но не лотерея на сотни руд.
```

### 7.2. Плутоний

`plutonium_ingot` существует в списке материалов, но **не является** центрифужной побочкой и не получает dedicated ore.

Его будущий источник:

```text
урановая ядерная цепочка → специальная переработка / трансмутация → плутоний
```

Эту механику не нужно подменять случайным шансом на уранините: она требует отдельной машины и отдельного дизайна радиации/топлива/реактора.

## 8. Материалы, которые понадобятся при реализации

### 8.1. Что нужно именно для ЦФ1УР

ЦФ1УР использует только чистые металлические пыли как гарантированный результат. Поэтому она не требует создания оксидов, солей или концентратов.

Уже существуют:

- `raw_*` формы всех 26 руд, включая `raw_calcite`;
- главные металлические пыли 22 строк ЦФ1УР;
- чистые пыли свинца, лития, неодима, висмута, рения, радия;
- кальциевый и магниевый самородки;
- ванильные `iron_nugget`, `gold_nugget`, `flint`.

В текущем checkout пока нет зарегистрированных:

```text
iron_dust
copper_dust
```

Они необходимы как побочки ЦФ1УР. Их нельзя незаметно заменить железным/медным слитком: таблица намеренно работает на уровне пылей. Если подготовленные 94 металлические пыли уже содержат эти изображения, при реализации нужно лишь корректно добавить registry/model/lang entries.

### 8.2. Материалы следующих уровней

Оксиды, соли и концентраты **не нужны ЦФ1УР**. Они появятся в ЦФ2УР и далее, где по утверждённому принципу будут дополнительным выходом наряду с металлической пылью.

Перед разработкой ЦФ2УР потребуется отдельная таблица:

```text
входной минерал → чистая пыль + конкретная соль/оксид + расширенные побочки
```

Именно для этого будущего уровня понадобятся изображения и registry entries вроде оксида алюминия, карбоната кальция, бората и вольфрамата. Их отсутствие не блокирует запуск ЦФ1УР.

## 9. Переход к плавке, восстановлению и заводу сплавов

### 9.1. ЦФ1УР, ЦФ2УР и переход к слитку

У ЦФ1УР путь намеренно простой:

```text
чистая металлическая пыль → плавка → слиток
```

Сложная химическая ветка начинается не раньше ЦФ2УР:

```text
ЦФ2УР: чистая пыль + соль/оксид → плавка или восстановление → слиток
ЦФ3УР: 2× чистая пыль + поздние побочки → старшая техника / сплавы
```

Какая машина выполняет восстановление оксидов и какие восстановители используются, будет определено одновременно с таблицей ЦФ2УР. ЦФ1УР не блокируется их отсутствием.

Простая прежняя переплавка руды/сырья в 1 слиток остаётся доступной как ранний обходной путь. Она не отменяет промышленный путь, поскольку не даёт побочек.

### 9.2. Задел для завода сплавов

Завод сплавов должен получать на вход **чистые металлические пыли** либо, если это будет отдельно разрешено, чистые слитки.

Он не должен принимать необработанные:

```text
руды;
raw-минералы;
соли;
оксиды;
минеральные концентраты.
```

Так границы систем остаются ясными:

```text
дробилка       — освобождает сырьё из рудного блока;
ЦФ1УР          — получает чистую металлическую пыль и базовые побочки;
ЦФ2УР / ЦФ3УР  — добавляют сложные химические формы и старшие выходы;
восстановление — получает чистый металл из химической формы ЦФ2УР+;
завод сплавов  — смешивает уже чистые металлы.
```

Существующие alloy ingot/dust items и задел `gonzotech_alloy` в item filtering не меняются этим концептом. Рецептуры сплавов, пропорции, 5×5 сетка, NBT-сплавы и output behavior должны быть отдельным документом/patch.

## 10. Требования к серверной логике машин

Эти правила следует соблюдать при реализации всех трёх станков, чтобы singleplayer и dedicated multiplayer работали одинаково:

1. Сервер, а не GUI, выбирает recipe и делает random roll.
2. Клиент получает только синхронизированное состояние inventory/progress.
3. Одна завершённая операция делает каждый chance roll ровно один раз.
4. Нельзя выполнить повторный roll из-за открытия GUI, chunk reload, повторной синхронизации или быстрого shift-click.
5. Если результат некуда положить, вход не уничтожается и редкая побочка не пропадает.
6. Извлечение output и вставка input должны использовать обычные server-authoritative item handlers/menus.
7. Host для дробилки определяется по фактическому block item входа, а не по данным, присланным клиентом.
8. Все recipe inputs должны использовать стабильные item/tag definitions, включая stone/deepslate/nether/calcite варианты руд.

## 11. Минимальный ручной test plan после реализации

### Дробилка

- Проверить по одному stone, deepslate, nether и calcite ore block.
- Проверить, что основной `raw_*` выдаётся всегда.
- Проверить независимость bonus raw и host-побочки на серии операций.
- Проверить, что рудный блок, добытый Silk Touch, принимается.
- Проверить, что `raw_*` предмет не принимается как повторный вход дробилки.
- Полностью заполнить output: вход не должен исчезнуть и operation не должна «съесть» chance.
- Проверить granite, diorite и andesite после утверждения их таблицы.

### Центрифуга

- Для каждого из 22 `raw_*` **и соответствующих рудных block items** проверить один и тот же гарантированный основной dust output.
- На серии сфалерита и уранинита проверить, что две-три побочки могут выпасть одной операцией.
- Проверить формулу шансов ЦФ1УР: в частности, 13.0% неодима и 8.5% радия статистически на крупной серии/тестовом seed.
- Проверить, что `raw_manganese`, а не несуществующая `manganese_dust`, появляется из касситерита/вольфрамита.
- Проверить block/output inventory: редкие результаты не исчезают.
- Проверить, что сера, марганец, йод и ртуть не получают неутверждённые recipes ЦФ1УР.

### Совместимость

- Простая печь по-прежнему даёт один слиток из старых руд/сырья.
- 5% свинца от iron ingot продолжает работать.
- Сохранённый мир с уже существующими ore blocks, raw items и ingots загружается без отсутствующих registry ID.
- На dedicated server два игрока не могут дублировать roll одной машины через GUI/reopen/latency.
